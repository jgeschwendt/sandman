sandman · bank format

Bank format — the on-disk contract

The format the commit path writes and every reader assumes. Each numeric claim below was measured against the production banks — 232 memory files across 33 banks (measured 2026-08-12 · the real_banks round-trip suite, re-runnable with cargo test -- --ignored).

bank key memory file MEMORY.md _archive/ _reflect.json log/ trail/ shifts/ breath/ score/ report concurrency design mcp

Bank key

One bank per working directory: the cwd with every non-alphanumeric character replaced by - (same encoding Claude Code uses for ~/.claude/projects/). /Users/you/.code/project → -Users-you--code-project. A linked git worktree (a .git file pointing into worktrees/) keys as its parent directory, so every branch of one repo shares one bank: ~/.grove/code/o/r/main → -Users-you--grove-code-o-r. The commit path takes a key only as one component recall reads: never empty, no /, \ or control character, no leading . or _ (the dotted runtime tier and _archive, which recall skips). A worktree nested in another checkout of the same repo (Claude Code's .claude/worktrees/<name>) keys as that checkout's project; a submodule, even inside a worktree, is its own project; a cwd that no longer exists beside a linked worktree keys as that worktree's project when every linked worktree beside it is of one repo, and as itself beside worktrees of two. A trailing separator or a . is dropped before keying — /x/./ keys as /x — so the CLI, the hooks and the MCP server agree.

Memory file

<type>_<slug>.md, where slug = name lowercased, every non-alphanumeric run → _, trimmed of leading/trailing _, truncated at 60 characters — characters, not bytes, here and in the index truncation below; byte truncation would split UTF-8 mid-sequence (48 of 232 descriptions carry non-ASCII inside the window). 39 of 232 files sit exactly at 60; the rule reproduced all 232 filenames with zero violations (measured 2026-08-12 · M1 round-trip suite).

---
name: <freeform — often a slug, sometimes prose>
description: <one line>
type: user | feedback | project | reference
created: <ISO-8601 Z>          (183/232)
source: <session/provenance>   (219/232)
updated: <ISO-8601 Z>          (183/232)
---

<markdown body>
  • Frontmatter values are single-line — zero multiline values in 232 files.
  • name, description, type are always present; the rest vary. Unknown keys occur (one file carries recall:) — parse must preserve unknown keys and key order; round-trip is byte-identical.
  • A blank line always separates the closing --- from the body (0 violations).
  • Collision suffixes: _2, _3, … append to the slug when the target filename exists and is not the file being replaced.

MEMORY.md — the bank index

Regenerated, never hand-edited. Fixed frontmatter, then one line per memory file, sorted by filename:

---
name: MEMORY index
description: One-line map of all durable memories in this knowledge bank
type: reference
---

- [<name>](<filename>) — <description, truncated at 150 chars>

(150 measured: max entry description is exactly 150 characters, hard cut, no ellipsis.) Descriptions are raw text end to end — no quoting layer ever interprets them.

_archive/ — supersession lineage

A replaced file moves (never copies) to _archive/<YYYYMMDDTHHMMSS>_<filename>, or <YYYYMMDDTHHMMSS>-<n>_<filename> (n from 2) when that name is already taken within the second, so names do not order archives within one second — UTC timestamp prefix, archived content verbatim as it stood. Nothing in _archive/ is ever deleted. A commit moves the files it replaces only once everything that can refuse it has passed — the index over the rest of the bank, each replaced file read, a free filename found — so a refused commit leaves the bank as it stood.

_reflect.json

Per-bank due-baseline: {"at": <ISO>, "count": <int>, "last_ops": <int>} — written only by reflect, seeded on first sight of a bank.

log/ — the voyage log

Not a bank. log/ is memory's derivative: one entry per UTC day, written by reflect from the memories that landed that day, and re-derivable from them at any time.

The four kinds are the four things the reference logs mark: discovery — something new exists or was named; milestone — something shipped, was adopted, or was retired for good; reflection — the day stepped back and changed how the work is done; setback — something was lost, broke, or went wrong, and what it cost.

The body is the entry: 2–4 sentences of prose. A final line beginning Next: is the optional hand-off to the day after.

The rules

  • Idempotent for the day. The entry is a function of the day's sources. Reflect rewrites <date>.md only when the fingerprint on disk no longer matches the one the day's sources hash to — same sources, same entry, no model call.
  • Never hand-edited. Pipeline-owned like memories/: an edit is lost on the next pass that finds the sources changed. A day the operator wants marked is marked by what remember puts in the banks that day.
  • A quiet day gets no file. No sources, no entry — the index shows the gap. A filler entry would be prose about nothing, and every reader of the log pays for it in context.

trail/ — the event log

Not a bank. trail/ is the machine's ledger: every autonomous decision is one event, appended and never edited, and every commit the machine makes names its event by trailer, so git log in any repo joins back to it.

trail/<yyyy>/<mm>/<dd>.jsonl — one file per UTC day, one JSON object per line, keys alphabetical, newest last:

{"at":"2026-10-09T23:41:02Z","branch":"perpetual","cost_usd":0.12,"id":"e-20261009T234102Z-7f3a","kind":"change","model":"opus","parent":null,"rationale":"…","refs":[],"repo":"jgeschwendt/sandman","sha":"9b32c84…","shift":"s-20261009T2300Z"}
key what
at when the event was appended, ISO-8601 Z; the file is the UTC day it falls on
branch the branch the work landed on
cost_usd what the work cost, US dollars, a non-negative number
id e-<yyyymmddThhmmss>Z-<4 hex> — the instant plus four random hex digits, unique within the day's file and so across the trail
kind what happened — one of the kinds below
model the model that did the work
parent the id of the event this one descends from, or null; must already be on the trail
rationale why, in prose
refs free strings — thread ids, URLs, memory files, repo@sha
repo the repo touched, owner/repo
sha the commit the work produced
shift the shift the event belongs to

at, id, kind, parent and refs are always present (refs may be []); every other key is omitted when it has no value, never null.

Kinds: breath · change · correction · decay · decision · guard · promote · reconcile · revoke · shift.handoff · shift.start. Any other kind is refused. decision is the owner's answer to a proposal, written by report serve only (its POST /answer, § report; trail append refuses it, exit 2) — a shift's own choice is a row of its report's Decisions table, and a change event if it changed code. promote and decay are proposals: the Sabbath appends them through trail append, the owner acts on them, and no verb emits or reads them yet.

The parent chain

An event's descendants are every event whose parent chain reaches it — a change made because of a promote, a guard made because of a correction. revoke and reconcile events name their target as parent too, but they speak about it rather than descend from it: the walk never enters them, so a second reconcile never reverts the first one's reverts.

Trailers

Every commit the machine makes carries two git trailers:

Shift: <shift-id>
Event: <event-id>

sandman trail trailers --shift S --event E prints exactly those lines, for appending to a message or for git commit --trailer.

Revoke and reconcile

  • Revoke appends a revoke event with parent: <id> and the reason as its rationale. Nothing is edited or deleted; revoking a revoked event appends nothing — the check and the append share one hold of .commit.lock, so racing revokes write one event.
  • A shift id revokes the whole shift. revoke and reconcile take an s-… id as readily as an e-… one: the revoked set is every event whose shift is that id (revoke and reconcile events aside) plus all their descendants, and a commit is a hit when its Event: is in the set or its Shift: is the id — so a commit whose event never reached the trail is still caught. revoke s-… appends one revoke event with parent: null and refs: ["shift:<id>"]; the reconcile event it leads to carries the same ref and no parent, on reconcile/<shift-id>.
  • Reconcile <id> takes the event and its descendants as the revoked set. In every repo it reaches — each checkout under ~/.grove/code/<owner>/<repo>/<branch>/ (repos from the grove manifest's [roots."owner/repo"] tables and from the tree itself), plus ~, ~/.routines and the data root — it selects the commits whose Event: trailer is in the set (or, for a shift id, whose Shift: names it), one pass per repository however many worktrees it has.
  • The base is the repo's trunk: the manifest root's trunk = "…" when it names one, else main, else the local branch refs/remotes/origin/HEAD names (never the remote-tracking ref itself) — never HEAD, since a shift/… checkout would carry the shift's other commits onto the reconcile branch. A manifest trunk that does not resolve to a branch fails the repo (failed, exit 1) rather than falling through; so does a repo where none of the three resolves, and that message asks the operator to name the trunk in ~/.grove/manifest.toml as trunk = "…" under the repo's [roots."owner/repo"] table. Nothing is reverted and no branch is cut. A trunk behind refs/remotes/origin/<trunk> (an ancestor of it, not equal) fails the repo too — fast-forward it (grove sync) and rerun — so a hit trunk does not reach, reported off trunk and left alone, is one that never landed.
  • The machine merges by rebase only. A shift never makes a merge commit, and its pull requests merge by rebase (§ shifts, Landing) — so every commit it lands sits on trunk's first-parent line and reverts on its own. A merge carrying a revoked Event: or Shift: trailer is therefore a shift that broke the rule: reconcile never reverts a merge, and refuses that repo as a conflict (exit 1) with a note naming the merge, nothing in it reverted. Merges without trailers are not hits and are never touched.
  • The hits trunk reaches are reverted newest-first (git rev-list --topo-order) onto reconcile/<id> — cut from trunk, or reused if it exists and still contains trunk (a reconcile branch trunk has moved past fails that repo: merge trunk in or delete the branch, then rerun); a hit the branch's history already reverts — its This reverts commit <sha>. line, written by a commit that is neither itself a hit nor itself reverted — is reported already reverted and skipped, as is a hit whose revert stages nothing (a hand revert without that line), so a rerun after a complete reconcile changes nothing and exits 0. The reverts happen in a scratch worktree, so no checkout is switched, and it is removed with --force however the pass ends. The repo's commit hooks are switched off (core.hooksPath=/dev/null, --no-verify): a revert is the owner's reconcile, not a shift's work, so a repo's hook suite neither blocks nor slows it. Each revert commit carries Shift: reconcile and Event: <the reconcile event's id>. A conflicting revert is aborted and ends that repo's pass; a reconcile/<id> branch the pass cut and reverted nothing onto — a first revert that conflicts — is deleted again. History is never reset or forced.
  • Reconcile then appends one reconcile event — parent: <id>, shift: reconcile, refs every reverted commit as repo@sha, rationale the count and every conflict — and lists the memories under memories/ whose source: names a revoked event, for reflect to retire. It modifies no memory. Every repo is worked before the verdict: reconcile exits 1 when any repo ended in a conflict or a failure, after the report has listed them all. A pass that reverts nothing and meets no conflict or failure appends no event, so a rerun leaves the trail as it was. --dry-run prints the plan and writes nothing.

$SANDMAN_GROVE_CODE moves the grove's code directory (the manifest is read beside it, <code>/../manifest.toml, and may be absent); $SANDMAN_RECONCILE_EXTRA (colon-separated) replaces the three extra repos.

shifts/ — the shift engine

Not a bank. A shift is one autonomous session bounded by the five-hour usage window; sandman shift opens it with a brief and closes it with a handoff. Its id is s-<yyyymmddThhmm>Z, the UTC minute shift brief ran, and every machine commit it makes carries that id in its Shift: trailer.

shifts/
  current.json            # the open shift; absent between shifts
  PAUSE                   # the owner's off switch — the runner starts nothing while it exists
  rotation.toml           # the owner's rotation: the repos `pick` leaves off
  s-20261016T1600Z/
    brief.md              # the composed prompt the session started from
    handoff.md            # what the shift left the next one
    meta.json
    report.md             # what the shift tells the owner (§ report)

current.json — one object, keys alphabetical, written by shift brief, extended by shift attach, removed by shift handoff for the shift it names:

key what
bg_id the background session's short id, once the runner has attached it
handoff_by when the shift must hand off — fifteen minutes before the window resets, or before five hours pass when the window is unknown, and never past the night's end
path the checkout the shift works
repo owner/repo
session_id the session's full id, once attached
shift the shift id
started when the brief was composed, ISO-8601 Z
theme the night's theme

meta.json — keys alphabetical: shift, theme, instrument, repo, path, started, mind (the orchestrator model), window (remaining as prose, resets_at, stale, used — the clock at the start); shift handoff adds ended, cost_usd when given --cost, abandoned: true when the runner found the session gone, and current.json's bg_id and session_id when the runner attached them — the lock goes, the ids stay for the reap; shift reaped --shift <id> stamps reaped once the runner has reaped the session. shift land adds landing and the runner's shift pr adds pr (§ Landing). The rotation reads repo and started from every meta.json to know which repo has rested longest.

The night

The owner works by day; the machine works nights. A night is $SANDMAN_SHIFT_NIGHT (HH-HH, New York hours 0–23, two different ones; default 21-07): from the first hour until the second, across midnight when the first is the later. Both shifts of a night carry the theme of the day it began on — its anchor, the New York date end hours before the instant when the night wraps midnight (Monday 02:00 and Sunday 22:00 are both Sunday's night), the plain New York date when it does not. Everything the creation week decides reads the anchor: the theme, the Sabbath (Saturday's night, into Sunday morning), one Sabbath a night, the Sabbath's pick, the rotation's and the score's Saturday-aside. shift clock --check refuses by day and close to dawn (§ The handoff and the clock), and handoff_by never runs past the night's end, so by day the runner's tick only closes a shift that overran. report serve keys its pages by the same anchor.

The rotation

shift pick covers the trunk checkout of every grove repo whose owner is in $SANDMAN_SHIFT_OWNERS (colon-separated, default jgeschwendt) — the trunk is the checkout named by the manifest root's trunk = "…", else main — and nothing else: only checkouts under $SANDMAN_GROVE_CODE/<owner>/ are candidates. The home repos (~, ~/.routines, the data root) are never picked, though reconcile still scans them: home-sync commits them every fifteen minutes without trailers, so a shift's work there could not be told from the sync's or revoked cleanly, and a shift working ~/.sandman or ~/.routines could edit the trail it answers to or the live runner that supervises it. Least recently shifted first, never-shifted before any; a tie goes to a failing stele check (run only where .stele/graph.lock exists, as CI runs it — under the trunk's pinned tools, mise x -C <trunk> -- stele check, bare only when mise is not on PATH — 20 s timeout, a missing binary skipped), then the most open threads naming the slug (a proposal: thread waiting on the owner, waiting: user, is no signal and not counted), then the most untried breaths (state: new or spiked) filed against it, then the name. On a Redesign night, repos with an approved proposal:<repo>:* thread (open, answer: approve, decided:, waiting: agent — the owner's message is the latest) come before all the rest, least recently shifted first among them; an approved thread whose latest message is the agent's (waiting: user) waits on the owner and promotes nothing. A repo is cooled when its newest shift (meta.json) started under 6 h ago and lasted under 15 min, started to ended: it gets neither that promotion nor the tie-break signals and competes on recency alone, named on stderr, skipped promotion: <repo> (cooled: last shift <m>m) — a signal its shifts cannot clear must not win it the night over and over. The open shift's repo and $SANDMAN_SHIFT_SKIP (colon-separated slugs) are passed over, and so is a repo the owner switched off — shifts/rotation.toml, versioned content, flat TOML (below) — each named once on stderr, skipped: <repo> (off), before a repo he froze: its section of the week's targets file (§ The brief and its slots) says freeze, frozen or on ice, or his answer on any proposal:<repo>:* thread — open or resolved, text under a ## user heading — says on ice, case aside. Each is named once on pick's (and brief's) stderr, skipped: <repo> (frozen). A shift started in Saturday's night never counts as a repo's last: the Sabbath works sandman whatever the rotation says, and must not stand in for its turn.

The rotation's file. shifts/rotation.toml holds one root key, off = ["owner/repo", …], sorted and deduped; absent or empty, every repo is on; any other key, or off not an array of strings, fails pick, brief and rotation (exit 1) rather than turn an off repo back on. sandman shift rotation [--off <repo>]… [--on <repo>]… prints each rotation trunk as <repo> · on|off · <last shifted, or never shifted>[ · frozen] — the owner's week's word, as above — and each off repo whose trunk is not found now as <repo> · off · not found, after the flags rewrite the list (--on applied last, and clears such a repo; a repo in neither exits 2 and writes nothing); the page's Rotation form (§ report) writes the same file. Every write holds .commit.lock, tmp → rename. The Sabbath's pick ignores the list.

The Sabbath's pick. In Saturday's night shift pick returns jgeschwendt/sandman's trunk — the machine's own repo, where the self-pass branch sabbath/<yyyy-Www> lives — rotation, the open shift and the skip list aside; it must be a rotation trunk (exit 1 otherwise) and trusted (the untrusted exit below).

One Sabbath a night. Once a shift with theme: Rest started in this night has handed off — its meta.json has ended — shift brief exits 1 with sabbath kept: <id> handed off at <ended>, and the runner waits; --dry-run still composes. The runner fires every tick, so without this a Sabbath that ends early is followed by another.

Trust. Claude Code asks once per directory whether to trust a workspace and records the answer in ~/.claude.json ($SANDMAN_CLAUDE_JSON overrides) as projects["<absolute path>"].hasTrustDialogAccepted; a parent's answer does not carry to its children. claude --bg refuses an untrusted cwd ("Workspace not trusted"), while claude -p skips the dialog, so a shift can only open where the owner has run claude once and accepted. shift pick passes over untrusted trunks; when only they remain it exits 1 with no trusted target: run claude once in each trunk and accept the trust prompt and their paths, one per line, and shift brief exits 3 on the same. shift pick --untrusted lists them (--path for paths). A missing or unparsable ~/.claude.json trusts nothing; an unparsable one is journaled. Sandman only reads it.

The brief and its slots

shift brief fills prompts/shift.md — in Saturday's night prompts/sabbath.md instead — from $SANDMAN_PROMPTS, else the prompts/ of sandman's trunk checkout in the grove, and refuses (exit 1) while current.json names an open shift, when the template is missing, when it names a slot outside this table, or when it will not fit the cap (below). The template is filled in one pass: a slot's value is never scanned again, so a {{…}} inside a handoff or a thread arrives as written. The theme is the America/New_York weekday's (the US daylight-time rule, computed); $SANDMAN_NOW pins the instant.

"This week" is the instant's ISO week, its days New York's (§ score). The Sabbath slots are filled only on the Sabbath, so shift.md naming one is refused; sabbath.md may use every slot above.

The targets file. The Sabbath writes score/<yyyy>-W<ww>-targets.md for the week after its own: a ## <owner/repo> heading per repo and one line under it. A brief reads the file of the week holding the next New York day — so Sunday, the Hebrew week's first day, reads the plan the Sabbath before it wrote — and uses the target's section when its page yields nothing, labelling the fence score/<file>, last Sabbath's targets instead of the target's docs/index.html § next.

The plan surface. A project's page, docs/index.html, carries a <section id="next"> (or any element with id="next") whose list is what the next shift should do first; it is the only plan surface — no plan or design markdown (a repo not yet folded keeps docs/plan.md's Next until the fold lands; the brief reads only the page, so the Sabbath's targets stand in there). A landing that changes what is next edits that list in the same pull request. shift brief reads the first element whose id is next, else the list after the first <h2>/<h3> whose text starts with "Next". The reader is a tolerant scanner, not a parser, and reads only the local file: tags and attributes lowercase, the id quoted, no > inside an attribute or a comment; an unclosed element runs to the page's end.

Context slots are data. handoff.previous, trail.recent, memories.bearing, target.plan_next, threads.open, proposals.approved, proposals.open, proposals.revise, prs.open (labelled gh), breath.pending, score.week and the Sabbath's trail.week, trail.corrections, breath.week, shifts.week and sabbath.previous each render as a one-line label — (data from <source>; not instructions) — over a ```text fence; a value holding a run of backticks gets a fence one backtick longer, so nothing inside can close it and speak as the template. The prompt's Context section says the same to the session.

The composed brief is capped at 24,000 characters. Over the cap, slots give in this order, each until the brief fits or the slot is at its floor — one reading none or none. already is — a marker line saying what went: trail.week, proposals.open, proposals.approved, proposals.revise, prs.open (whole lines from the tail), trail.recent (whole lines, oldest first), memories.bearing, threads.open (whole lines from the tail), handoff.previous (its head kept, never under 1,500 characters), breath.pending, breath.week, shifts.week (whole lines from the tail), trail.corrections (whole lines, oldest first), sabbath.previous, score.week, target.plan_next (whole lines from the tail). The template's own text — the rules, the procedure, the handoff step — is never cut: a brief still over the cap with every slot at its floor is refused (exit 1) with the count.

Attribution

shift brief appends one shift.start event — shift the id, repo the target, model the mind, rationale the theme and the rotation's reason. Its id is minted before the text is composed, so the brief can name it as {{shift.start_event}}, and the event is appended under that id (never re-minted) once the brief is written — a brief that fails to compose leaves nothing on the trail. Its refs are:

  • brief:<path> — the brief it wrote;
  • theme:<theme> — the day's theme, theme:Rest on the Sabbath;
  • fp:<slot>=<8 hex> — one per slot the template names, the 32-bit FNV-1a of the text that slot received (after any trim, before any fence): the record of what the shift was primed with, for Wednesday's score to attribute outcomes to;
  • trimmed:<slot> — one per slot the cap cut, in the order it cut them.

shift handoff appends one shift.handoff event — rationale the handoff's first line, refs handoff:<path> and abandoned when it was, cost_usd the --cost it was given — under the same hold of .commit.lock as meta.json's ended, before current.json is released.

Landing

Trunk is never pushed, by a shift or by the runner: every landing is a pull request, and it merges by rebase — linear history, each commit's message and Shift:/Event: trailers kept, its sha rewritten. Reconcile finds commits by trailer (git log --all), so the rewritten copy on trunk is still a hit; the branch's pre-merge copies, trunk never reaches, are reported off trunk.

  1. The shift lands. Gated green (prompts/shift.md rule 2), it rebases its branch onto the local origin/main — a session can neither fetch nor push, and grove-sync fetches every trunk each five minutes — and runs shift land --shift <id> --branch <name>. It refuses (exit 1) a shift already handed off, a branch the repository at the shift's path lacks, one not containing refs/remotes/origin/main, one adding nothing to it, and one any commit of whose origin/main..<branch> lacks a Shift: or an Event: trailer, naming the oldest such sha; else it writes landing: {at, base, branch, head} into the shift's meta.json — base the origin/main sha, head the branch's — and prints the summary. A re-land before the handoff replaces it, and handoff keeps it. Every earlier shift those trailers name whose landing is unsettled and whose landed commits this branch carries on, patch for patch (git cherry, so a rebase still counts) gets landing.superseded_by: <id>: a shift fixing another's red pull request branches from it, so its own carries the original commits on; a trailer alone supersedes nothing, and a re-land that no longer carries an unsettled landing on takes its stamp back.
  2. The runner opens it — the landing pass, every tick (docs/routines/shift.md). For each meta.json with ended, a landing not superseded and no pr: push <head>:refs/heads/<branch> unless refs/remotes/origin/<branch> is already head — never forced; a refusal is a correction push rejected: <the first error:, fatal: or ! line> once per (shift, head), $ROUTINE_STATE_DIR/rejected/<shift> holding the sha (written before the push, so a gate the watchdog kills counts), retried when the head moves or six hours pass — then gh pr create --base main --head <branch> --title "<theme> <id> · <repo>" --body-file shifts/<id>/report.md (handoff.md without one), and shift pr --shift <id> --number N --url U records pr: {number, opened, url}. A pull request already open for the branch is adopted from gh's refusal, which names it.
  3. CI decides; GitHub or the runner merges — the merge pass, run before the landing pass so a pull request is first read a tick after it opened, its checks registered. For each pr neither merged nor closed, gh pr view --json state,mergeStateStatus,statusCheckRollup,headRefOid:
    • MERGED: shift pr --merged, a change event merged PR <url>, and the local trunk fetched and fast-forwarded (merge --ff-only @{upstream}) when its tracked files are clean.
    • CLOSED: shift pr --closed, and a correction PR <url> closed unmerged unless it was superseded.
    • superseded: gh pr close --delete-branch, its comment naming the successor; shift pr --closed.
    • red — a check concluded other than SUCCESS, SKIPPED or NEUTRAL, or mergeStateStatus: DIRTY: a correction CI red on PR <url>: <failing checks> and shift pr --red <head>, once per head.
    • BEHIND (green or pending): gh pr update-branch --rebase, once a tick, a stderr line updated PR <url> onto main and no event. A personal account gets no merge queue, so strict required checks hold auto-merge until the branch is current, and GitHub rebases it server-side; the next tick reads the new head and its checks. The local landing.head is then stale, which is fine: the landing pass runs only for shifts with no pr yet.
    • otherwise the first look whose merge state is known sets pr.auto. A branch nothing blocks (CLEAN, HAS_HOOKS, UNSTABLE) is false: gh pr merge --auto would merge it at once, CI or not (gh's isImmediatelyMergeable, pkg/cmd/pr/merge/merge.go, read 2026-10-13). Any other tries gh pr merge --auto --rebase --delete-branch: a public repo's ruleset — required checks, strict — takes it, true; a refusal is false. An auto: false pull request whose checks all concluded green, none pending, is merged here, gh pr merge --rebase --delete-branch; the next tick reads it merged.
  4. The next shift sees it. prs.open (§ The brief and its slots) lists the target's pull requests neither merged, closed nor superseded; a CI red one is that shift's first work (prompts/shift.md Procedure 3).

Nothing is configured per repo: public repos with a ruleset take the auto: true path; private ones, which the free plan gives no rulesets or auto-merge, the auto: false one. shift pr --shift <id> takes one mark per call — --number N --url U (writes pr whole, stamped opened), --auto true|false, --red <sha>, --merged, --closed (each an instant) — and refuses (exit 1) a shift with no landing, or a mark before pr.

The local trunk — ~/.grove/code/<owner>/<repo>/main — is never ahead of origin: no shift commits to it, and after a merge the sweep, else grove-sync, fast-forwards it.

The handoff and the clock

  • A handoff carries the shift's cost. --cost USD is the session's own total, read from its final result: turn, written as the event's cost_usd; --cost 0 (it could not read one) journals a cost zero note. The runner's --abandoned passes none.
  • A handoff needs a report. Every shift handoff but --abandoned refuses — exit 1 naming shifts/<id>/report.md, nothing written, the shift still open — while the report is missing, lacks one of its five headings in order, or is over 6,000 characters (§ report). The runner recording a dead session has nobody to write one.
  • A shift is handed off once. A second shift handoff exits 1 shift <id> was handed off at <ended>; a current.json still naming it — a handoff that died before the release — is released, and the refusal says so, once the trail holds the shift's shift.handoff: one is appended from meta.json (cost_usd, abandoned, the first line of handoff.md) when it does not.
  • A handoff is at most 2,000 characters. shift handoff refuses a longer handoff.md (or --file) — exit 1 with the count, nothing written, the shift still open — unless --truncate, which keeps the head and appends a note of how many characters went, the whole within the cap. --abandoned always truncates: the runner recording a dead session has nobody to send back to shorten the file.
  • An abandoned handoff says why when the runner does. --abandoned alone keeps a handoff.md the session wrote, else writes Abandoned: the shift runner found the session gone at <instant> with no handoff written. With --reason TEXT (only beside --abandoned — without it, even an empty one exits 2; the runner's overrun path passes stopped at <time>: still working <n> min past handoff_by) the handoff opens with the line Abandoned: <reason> — above whatever the session wrote — and so the shift.handoff event's rationale reads the same.
  • The runner's landing sweep opens every tick, before it looks for an open shift — a session that hands itself off with --from-session has removed current.json by then — with ~/.local/bin and mise's shims on PATH for gh and git; the branch push is --no-verify, since the trunk checkout's pre-push hook would test main, not the branch, and the pull request's CI is the gate (§ Landing).
  • A session that never started is abandoned in ten minutes. When dispatch lists the shift's session working with no transcript (no last_activity) more than ten minutes after started, it is waiting on a start-up prompt a dontAsk session cannot answer (§ The sandbox, project MCP servers): the close block stops it, hands off --abandoned --reason "session never started (a project MCP prompt?)" and appends a correction.
  • The sweep reaps. The owner keeps no machine session in his history — not in claude agents, not in the desktop app's list. In the same sweep, for every shifts/s-*/meta.json and breath/passes/*/pass.json with ended and no reaped: when it names a bg_id and dispatch's claude list shows that session done, failed or stopped, claude rm it (a failure ignored); absent from the listing, go on; working, blocked or no answer, leave it for the next tick — a live transcript is never taken. Then sandman take <session_id> --force moves the transcript out of ~/.claude/projects into the archive (dispatch's state, not the file's mtime, is the proof it is over; "no transcript" means already taken), and shift reaped / breathe reaped stamps reaped, so each is reaped once. A shift ended before its meta.json carried the ids is stamped with nothing removed. The close block itself rms only the strays it stopped under a shift's name, three seconds after the stop.
  • shift clock --check exits 0 when a shift may start, 1 when it must not — by day (day: the night opens at <instant>), under $SANDMAN_SHIFT_MIN_WINDOW_MIN (default 60) minutes of night left (night ends in <m>m) or of window left, or 90 % of the window used — and 3 on a fault. handoff_by stays fifteen minutes before the reset and never past dawn, so with the default floor a shift always has at least 45 minutes of work: one the reset or the morning would cut shorter is never opened.
  • A stale window file is unknown. The statusline that writes it runs only beside an interactive session, so overnight it goes stale: a file whose at is more than 30 minutes old, or that has no at, reads exactly as a missing one — never a refusal, the runner's timeout the bound — and shift clock and shift status print window=unknown (stale since <at>).
  • The window file's faults. A missing or stale file is unknown, never a refusal. A file that is there is a fault — exit 3 from plain shift clock and from --check, for the runner to report rather than wait on — when it cannot be read or parsed, is not a JSON object, has no five_hour object, carries a five_hour.resets_at or five_hour.used_percentage that is missing, null or not a number, a negative used_percentage, an at more than five minutes after now (a writer whose clock runs ahead), or resets more than six hours after now (a five-hour window cannot; a days-ahead or millisecond resets_at is a writer's bug). shift brief and shift status read a faulty window as unknown.

The sandbox

Shift and breath sessions run permission_mode: dontAsk inside Claude Code's strict Bash sandbox, under the settings sandman shift profile [--kind shift|breath] prints — profiles/session.json, compiled into the binary, one profile for both kinds today (--kind is there so they can diverge). Strict means allowUnsandboxedCommands: false: a command the sandbox refuses fails rather than retrying outside it. Writes reach only ~/.grove (the checkouts, and the bare repositories and manifest lock under ~/.grove/roots and ~/.grove that every commit and grove tree add write — observed 2026-10-10, the first Sabbath could not cut its branch with ~/.grove/code alone), ~/.local/state/claude, ~/.local/state/mise (mise records a config's trust there; without it every mise x -C <worktree> failed EPERM, observed 2026-10-12), the toolchain caches ~/.bun, ~/.cache, ~/.cargo, ~/.hex, ~/.mix and ~/Library/Caches (mise's, and mr-boxington's under ~/Library/Caches/mbx, which wraps mise's rust — mbx[error]: Operation not permitted without it, observed 2026-10-13), ~/.routines, ~/.sandman and ~/.docket (the docket CLI writes ~/.docket/<id>.md); denyWrite takes back the caches' bin/ directories and cargo's config, which the host runs later. These cache lists are profiles/shift-test.sb's write allowances and denials: change one, change both; ~/.aws, ~/.netrc, ~/.npmrc, ~/.ssh and ~/Codes cannot be read; the network reaches only the profile's allowedDomains — among them api.anthropic.com, because sandman reflect and sandman dream run claude -p from Bash, inside the sandbox (observed 2026-10-10: the first Sabbath's reflect was denied).

dontAsk runs what permissions.allow names — the profile lists the tools a shift uses, bare, and the docket and sandman MCP tools — and denies everything else without asking; permissions.additionalDirectories puts ~/.grove/code, ~/.routines and ~/.sandman among the working directories, so Edit and Write reach them from any cwd.

  • Not bypassPermissions. The sandbox's proxy asks about a domain outside allowedDomains, and bypassPermissions answers yes: probed 2026-10-09 on 2.1.296, a curl https://example.com under the profile returned 200 in bypassPermissions and deny network-outbound example.com:443 (user denied) in dontAsk. The allowlist only holds in a mode that never says yes on its own.
  • Git's network commands run outside the sandbox. git fetch, git pull, git push and grove sync are excludedCommands (beside shift-test, below), run with the host's own git auth: git over SSH fails inside the macOS sandbox, and a --bg session inherits no environment to carry a token in.
  • Some paths no allowWrite reaches. The sandbox protects .claude/skills, .claude/agents, .claude/commands, .claude/hooks, the .claude settings files and .mcp.json "in your working directory and the directories above it", and ~/.claude almost entirely, whatever allowWrite says (https://code.claude.com/docs/en/sandboxing, fetched 2026-10-12). A skill whose workspace is ~/.claude/plans/<slug>/ works in ~/.sandman/shifts/<id>/<slug>/ instead (prompts/shift.md rule 7).
  • Tests run in a second sandbox. Inside Claude Code's, a test suite cannot bind loopback, open a pty, run ps or read /dev/fd (process substitution). An excludedCommands entry would run with no sandbox at all — no proxy, no denyRead — so exactly one command leaves: ~/.local/bin/shift-test <test command>, which re-enters its own Seatbelt profile, profiles/shift-test.sb (both installed by the sandman-install routine, docs/routines/sandman-install.md, with the binary). It runs only from under ~/.grove/code, and from (allow default) it subtracts: reads of ~/.aws, ~/.claude, ~/.claude.json, ~/.config/gh, ~/.docker/config.json, ~/.gnupg, ~/.netrc, ~/.npmrc, ~/.ssh, ~/Codes and ~/Library/Keychains; writes outside ~/.grove, the toolchain caches (~/.bun, ~/.cache, ~/.cargo, ~/.hex, ~/.mix, ~/Library/Caches, mise's state), temp, the ptys and the working tree — and inside them, toolchain binaries and config and the files Claude Code's sandbox write-protects in a checkout (git hooks and config, .claude/ agent config, .mcp.json, editor tasks); every network peer but loopback, less the machine's services (1701, 1703, 1705, 7777) and the unix sockets of launchd's listeners (ssh-agent), /var/run (docker, DNS), docker and gpg; and the exec of ssh, scp, sftp, security, osascript, open and launchctl. ps is setuid, which no sandboxed process may exec, so it alone runs unconfined. The wrapper drops the proxy and agent variables, takes the home from the user database rather than $HOME, and sets CARGO_NET_OFFLINE, HEX_OFFLINE and MIX_ENV=test. The matcher is literal and keys on the spelling: probed 2026-10-12 on 2.1.296, the absolute entry let out only the ~/… spelling and the ~/… entry only the absolute one, so the profile lists both — the absolute one as {{HOME}}/…, which shift profile renders as $HOME — and denies a bare shift-test. Every command in a call must match for it to leave, and a call holding cd, a pipe, a redirect, && or $(…) stays sandboxed, where nested sandbox-exec fails sandbox_apply: Operation not permitted (observed 2026-10-13: … bun test 2>&1 | tail -15); the wrapper probes for that first and exits 71 with shift-test: still inside the session sandbox — make it the whole Bash call: …. So a shift names its worktree with -C <dir> instead of a cd (a spawned Agent's cwd resets each call) and captures output with shift-test -C <dir> --log <file> <command…>, which writes stdout and stderr to <file> — under the working tree or getconf DARWIN_USER_TEMP_DIR (never the caller's $TMPDIR), else exit 2 naming both — then prints it and exits with the command's status (prompts/shift.md rule 7).
  • Pushing is the runner's. git push from a session fails at the sandbox proxy despite excludedCommands — "This proxy requires authentication", exit 128 (observed 2026-10-11) — so a shift records its landing (shift land) and never pushes; the runner, on the host with working SSH and gh, pushes the branch and opens the pull request (§ Landing).
  • No project MCP server starts. Claude Code asks once to approve a repo's .mcp.json servers, and a --bg dontAsk session can never answer: stele's trunk, the one with a .mcp.json (stele serve), sat at "starting…" until handoff_by two nights running (observed 2026-10-12/13). The profile's disabledMcpjsonServers lists every server name in a rotation trunk's .mcp.json — today stele — and a new one is added by hand. Never enableAllProjectMcpServers: it would run any repo-authored command outside the sandbox.
  • Scratch and fallbacks. Claude Code names $CLAUDE_JOB_DIR/tmp (under ~/.claude, unwritable) as scratch; a shift uses ~/.sandman/shifts/<id>/tmp/. grove tree add refuses a root the manifest does not declare; the shift falls back to git -C <trunk> worktree add ../shift-<id> -b shift/<id>. A commit hook that fails EPERM in the sandbox (a pre-commit running cargo test) may be skipped with --no-verify: CI on the pull request is the gate, never skipped (prompts/shift.md rule 7).
  • The runner is canonical here. docs/routines/shift.md is the source of ~/.routines/shift.md; the sandman-install routine copies every docs/routines/*.md over an installed copy that carries no local edit. A shift may fix the installed runner in place; the owner's session reconciles this canonical copy with it, and the routine leaves the edited copy alone until he does.
  • Installing a binary is never a shift's act. ~/.local/bin is not writable, so a shift builds and tests its binary but never replaces the installed one; the sandman-install routine (docs/routines/sandman-install.md), running as the owner every fifteen minutes, builds a clean trunk and installs it, the sandbox files and the routines, then restarts the report agent.
  • Deny rules and the mod's guards hold in every mode. No mode skips permissions.deny — the profile denies git checkout --, git clean, git reset, git stash, force pushes and pkill -f — nor the mod's tool-call hooks.

breath/problems.md

The ruach's reading list, kept by shift brief: one ## <repo> · <yyyy-mm-dd> section per repo per local day — the target's plan-next, its open threads, and the newest five guard/correction events touching it — replaced in place when the same heading is briefed again.

breath/ — the ruach

Not a bank. The ruach is the research engine beside the shifts: a Claude session reads the feeds against the open problems and files what bears on a repo as a breath. sandman breathe is the store and the prompt composer; it never calls a model or the network.

breath/
  sources.toml                    # the feeds and their learned state
  problems.md                     # written by `shift brief` (§ shifts); read-only here
  <yyyy-mm-dd>-<slug>.md          # one breath
  ledger/                         # /gigaresearch's claim ledger
  passes/<pass-id>/pass.json      # one record per pass
  passes/<pass-id>/prompt.md      # the prompt the pass's session got

breathe init creates breath/, ledger/ and passes/ and copies the seed — the repo's breath/sources.toml, compiled into the binary — when sources.toml is absent.

sources.toml

Flat TOML: an optional root key reweighted (ISO-8601 Z, when reweight last ran), then one [name] table per feed, a bare key. Values are strings, integers, floats and one-line string arrays; anything else — a dotted or nested table, an inline table, a boolean, a date, a multi-line value, an unknown key — is refused with its line.

key what
kind atom · rss · json · html — how a reader parses the feed
url the feed
weight learned, ≥ 0; reweight moves it
budget items a pass reads from it at most
bears_on repo slugs (owner/name) or "*"
cursor where the last pass stopped, in the feed's own terms — written by close
last_read when a pass last read it, ISO-8601 Z — written by close
filed breaths filed from it — counted by file
adopted breaths from it adopted — counted by adopt
silent_since since when it has gone without an adoption — set by close and drop when absent, restarted by adopt and by a silence penalty

The first five are required. Every verb that rewrites the file — file --source, adopt, drop, close, reweight — sorts the tables by name, writes the keys in the order above with the state keys only when set, and drops comments.

A source is due for a skim when its last_read is absent or at least an hour old; a deep pass reads every source.

A breath

<yyyy-mm-dd>-<slug>.md — the UTC date file ran, the title slugged with dashes (cut at 60 characters, breath when nothing is left), -2, -3, … on a collision. Frontmatter in this order, one line per key, newlines in a value folded to spaces:

key what
title the idea
url its primary source
source the sources.toml table it came from, when named
repo the repo it bears on, owner/name or *
problem the open problem it speaks to
state new · spiked · adopted · dropped
bearing 0–1, the judge's "does it bear on the repo", when given
novelty 0–1, the judge's "is it new to us", when given
filed when it was filed, ISO-8601 Z
updated when it last changed
adopted when adopt ran, ISO-8601 Z — adopted only; what reweight counts by
seen_again later filings that matched it
reason why it was dropped — dropped only

The body is the four-line summary.

Dedupe. file matches a new filing against the breaths in the store — the same URL once both are normalized (http read as https, scheme and host lowercased, a trailing / and the utm_* query parameters dropped, an arXiv id's version suffix such as v2 cut; the fragment and every other query parameter, ref included, are kept — /#/post/1 and ?ref=v1 name pages of their own), else, within the same repo only, a title whose token Jaccard (lowercase alphanumeric runs) is at least 0.6 and whose numbers — the \d+(\.\d+)* runs, in order — are the same list — so Release 1.1.0 is never a repeat of 1.0.0, nor 2 of 10 of 10 of 2. A dropped breath is matched only by a filing for its own repo: a drop never blocks another repo. A match bumps that breath's seen_again and updated, prints seen_again <path> and appends nothing to the trail.

Transitions. spike takes new; adopt takes new or spiked; drop takes anything not yet dropped and requires --reason. Each stamps updated; adopt also stamps adopted.

passes/

breathe pass --kind skim|deep composes the pass prompt and writes passes/<id>/pass.json, keys alphabetical:

key what
bg_id the background session's short id, once attach records it
cost_usd what the pass cost, US dollars — null until close, or the dead charge
dead true when a later pass found it open past its timeout; absent otherwise
dropped · filed · read the pass's counters — null until close
ended when close ran, or when it was marked dead — null until then
id b-<yyyymmddThhmmss>Z-<kind>, the UTC instant pass ran
kind skim or deep
reaped when the shift runner removed its session and took its transcript (breathe reaped --id <id>); absent until then
session_id the session's full id, once attached
sources the due sources the prompt listed, by name
started when the prompt was composed

An open pass is in flight until its timeout — 15 minutes from started for a skim, 60 for a deep pass — and dead after it: its session is gone or overran, and nothing will close it. pass marks every dead pass it finds (ended now, dead: true, cost_usd $SANDMAN_BREATH_DEAD_COST_USD, default 2), so a pass that never closes is charged rather than free. An overrunning session's close still lands on its pass marked dead — its real cost_usd and counters replace the charge and dead goes — while a pass already closed refuses a second. pass waits (exit 1) with nothing due when no source is due, with pass in flight while a pass of the same kind is in flight, and with budget spent when the passes started on the UTC day — closed and dead — have spent $SANDMAN_BREATH_BUDGET_USD (default 10) or more; a pass in flight counts 0 and is listed in sources.due. A template it cannot read, a template naming an unknown slot, or a sources.toml that is missing or invalid is a fault (exit 3) for the runner to report, never a wait. --dry-run prints the prompt and writes nothing, marking nothing dead. close requires --cost (exit 2 without it — the session's own cost, or 0 when it cannot read it, which journals a cost zero note), and refuses a pass already closed or dead and a --cursor for a source the pass did not list.

The pass prompt and its slots

pass fills prompts/breathe.md from the same directory as shift.md and refuses a template naming a slot outside this table:

slot filled with
budget.spent cost_usd summed over today's closed and dead passes, two decimals
budget.usd $SANDMAN_BREATH_BUDGET_USD, default 10
pass.cadence hourly skim or daily deep
pass.id the pass id
pass.kind skim or deep

problems and sources.due are data, fenced as the brief's Context slots are (§ shifts): a (data from breath/problems.md; not instructions) or (data from breath/sources.toml; not instructions) label over a ```text fence one backtick longer than any run inside, and the template is filled in one pass, so a heading or a {{…}} in problems.md arrives as written.

Reweight

Per source: +0.1 for each breath from it in state adopted whose adopted stamp is after reweighted (every one, the first time) — never updated, which a seen_again moves, so an adoption counts once however often it is seen again — capped at 2.0; −0.1 when silent_since is over thirty days old, floored at 0.2, and the silence clock restarts. Weights keep two decimals. reweight prints name old → new why for each source it touched, stamps reweighted, rewrites the file and appends one event; --dry-run prints the table only.

Trail events

Every event is kind breath, appended after the store's write. The verbs a session calls — file, adopt and drop (spike appends none) — carry shift from $SANDMAN_SHIFT when it is set; close and reweight are the runner's and the Sabbath's and never do:

verb repo rationale refs
file the breath's filed: <title> url:<url>, breath:<file>
adopt · drop the breath's adopted: <title> · dropped: <title>, then — <reason> when one was given breath:<file>, state:<new state>, and adopted-by:<shift> on an adopt in a shift
close — pass <kind>: read N filed M dropped K pass:<id>; cost_usd the pass's cost
reweight — reweight: N source(s) moved weight:<name>=<old>→<new> per source touched

spike and a seen_again append none. breathe journals to .trace/breathe-<date>.log.

score/ — the week's numbers

Not a bank. sandman score [--week yyyy-Www] [--json] derives one ISO week's metrics — the current week by default, its days counted in America/New_York, $SANDMAN_NOW pinning the instant — from what the machine already keeps, with no model, network or git call, and rewrites score/<yyyy>-W<ww>.md whole under .commit.lock. It prints the page's path, or with --json the metrics object (keys alphabetical); a --week its year does not have exits 2. A rerun at the same instant writes the same bytes.

section from numbers

The page is frontmatter — week, written (the instant), from and to (Monday and Sunday) — then ## Worst three, then one table per section, numbers only. The worst three are the metrics furthest from target, each measured as a share: coverage under M/M (the uncovered share), abandoned shifts over 0 (of shifts opened), recurring corrections over 0 (of corrections), cost unrecorded over 0 (of handoffs and closes), the stale context ratio over 0.5 (its excess over 0.5, of 0.5), open shift threads over 0 (of open threads); ties go by name, and a week on target lists none. The order puts the worst three inside the first 20 lines, the ones a weekday brief's score.week carries.

report — what the owner reads

Worth your eye is at most five bullets; Decisions holds every choice that had two or more live options. shift handoff checks only the cap and the headings; the rest is the prompts' (prompts/shift.md Procedure 5).

Proposals ride threads. Work larger than one shift is never started unapproved: the shift opens docket open "<title>" --kind decision --key proposal:<owner/repo>:<slug> --option approve --option revise --option decline --body -, the body a comparison matrix — a markdown table, the options down the first column, criteria across the rest (cost in shifts, risk, coverage impact, reversibility, …), the recommended row in **bold** — then a paragraph of scope and the number of shifts it would take. The brief reads them back (proposals.approved, proposals.open, proposals.revise, § shifts); the owner answers with docket reply <id> --answer approve. A revise hands the thread to the agent; the next shift on the repo replies on it with a revised matrix (docket reply <id> --as agent --body -), which hands it back to the owner, answer: revise still in its frontmatter until his next answer overwrites it.

sandman report reads shifts/*/report.md and ~/.docket ($SANDMAN_DOCKET) — no model, network or git — and prints, in order: # Reports since <cursor or 'the beginning'> (# Reports in <week> under --week), ## Worth your eye (every selected report's bullets, each suffixed — <shift id>), ## Proposals awaiting you (- <key> · <title> · opened <ts> per open proposal: thread with waiting: user, whatever he answered before), then each report verbatim, newest first, under a --- rule; with neither reports nor proposals, the header and nothing new.. Reports are selected by their shift's started: by default those after the read cursor; --since <instant> (at or after), --week yyyy-Www and --all ignore it. --mark-read moves the cursor to the newest printed report's start, never back.

The cursor is .reports-read, one ISO-8601 line — runtime state in the dotted tier, gitignored by the operator's data-root repo like shifts/current.json, written atomic and outside .commit.lock (a last-writer-wins pointer, never content). Only the owner's eyes move it: report serve's GET / of the newest night (no ?night=, no foreign Sec-Fetch-Site) moves it to the newest report on that page, and --mark-read to the newest printed; --hook never does, since a hook that guessed wrong about whose session it primed would spend the owner's digest on a machine session (observed 2026-10-12 · s-20261012T0515Z read it before attach named its session).

report --hook reads a SessionStart payload on stdin and answers with recall's hook envelope (additionalContext): the unread digest, cut to 6,000 characters by dropping whole reports oldest first with a line saying how many went — never the Worth-your-eye or Proposals sections — and leaves the cursor, so every session start shows the unread reports until the owner opens the page. It prints nothing when nothing is unread, and nothing for the machine's own sessions — the hook skip rule: a payload session_id equal to shifts/current.json's; a cwd equal to its path, both canonicalized (SessionStart fires before shift attach writes the session id); or a cwd under the data root (breath passes, dream minds).

The UI — sandman report serve [--bind 127.0.0.1:1705] — makes the report a page, std-only HTTP/1.1 one request at a time (Connection: close), loopback only (any other --bind exits 2); it prints listening on http://<address> and serves until killed (--requests N answers N, then exits — the tests' seam). GET / is a night (§ shifts, The night) — the newest with a shift, which moves the cursor (above) unless Sec-Fetch-Site names another site (anything but none or same-origin: another page's <img> carries no Origin), or ?night=yyyy-mm-dd by its anchor date, which does not, 404 when no shift began in it: a header <Day>→<Day> night · <n> shifts · $<cost> · <landed> landed · <proposals> proposals (cost summed over the shifts' meta.json cost_usd, landed the rows of their Landed tables), then Proposals awaiting you — every repo's, each open proposal: thread with waiting: user, re-asked ones included, with its title, repo, opened time, body up to the last exchange (a matrix renders as a table), that exchange — the latest message whose header carries · answer: and the replies after it — as a <blockquote>, and a form of approve · revise · decline with an optional note — then Rotation, one form of every rotation trunk (§ shifts, The rotation) as a row: a checkbox name="on" value="<repo>" (id rot-<slug>) checked unless the repo is off, its label, its last shifted time and a frozen mark when the week's word froze it, and one Save — then Worth your eye (each bullet linking its shift), Landed (one table, a shift column first), every shift as a <details> holding its whole report, and the last 14 nights. The markdown rendered is exactly what reports use — #/## headings, - bullets, pipe tables, paragraphs, `code`, **bold** — everything else and every datum HTML-escaped; no script, no external fetch, the style inline in ui's green-and-gold palette. POST /answer (key, answer, note) finds the open proposal: thread with that key, runs docket reply <id> --as user --answer <answer> plus --body <note> when the note is non-empty ($SANDMAN_DOCKET_BIN, else ~/.local/bin/docket), appends a decision event (rationale owner <answer>d proposal <key>, ref thread:<id>, the key's repo) and answers 303 to /: 400 for another answer, 404 for an unknown key, 502 with thread's stderr when it fails, 500 when the trail refuses. POST /rotation (on=<repo>, repeated — what the checked boxes send) leaves off every rotation trunk the body does not name, ignoring names outside the rotation — an off repo whose trunk is not found now is a box too, unchecked — writes shifts/rotation.toml, appends a guard event (rationale owner set the rotation: off = [...], the file's line) and answers 303 to /, 500 when the file or the trail refuses; a rotation file that will not read makes GET / a 500. Both POSTs answer to the same Host and Origin checks. A request whose Host is not the bound address, or whose Origin is not http://<bound address>, is 403 — no rebinding DNS name or foreign form reaches it; other paths 404, other methods 405. Open it at http://127.0.0.1:1705, never localhost, which the Host check refuses. The launchd agent launchd/dev.gigantic.sandman.report.plist keeps it up (log ~/Library/Logs/dev.gigantic.sandman.report.log). launchd expands no ~, so the file is a template: sandman report plist prints it with {{HOME}} spelled out as $HOME, and $SANDMAN_SHIFT_NIGHT, when set in the rendering shell, added to the agent's environment (the label was io.jlg.sandman-report until 2026-10-20; the first two commands retire it):

launchctl bootout gui/$(id -u)/io.jlg.sandman-report 2>/dev/null; rm -f ~/Library/LaunchAgents/io.jlg.sandman-report.plist; sandman report plist > ~/Library/LaunchAgents/dev.gigantic.sandman.report.plist && launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.gigantic.sandman.report.plist

Concurrency

All bank, trail, shift, breath and score writes happen under .commit.lock at the data root, and every writer waits alike — up to five seconds for a holder to finish — before it reports the lock held; every file write is atomic (tmp → rename in the same directory).
