memory for agentic sessions · the main page · recall · knowledge

Prospective memory is remembering to do something later. sandman keeps one place for work the person defers — "do this later", "tomorrow", "after grove ships" — and surfaces it to the first session it comes due in. It never does the work: due items are raised with the person.

Built: defer, due, done, drop, the store, the seed's due block, the MCP tools and chart's list. Not built: matching an event to a session, a timeline in bifrost (next).

The problem

A deferred ask dies with the chat. "Let's do that tomorrow" is a turn in one transcript; the next session starts without it, and a memory is the wrong home: memories record what holds, not what is owed, and recall pulls them by relevance to the work at hand, never by date. The owner, 2026-11-14: "you should have a calendar or timeline too, i'll often tell you things like well do this later or tmrw, you should have one place for these types of turns".

Time-based and event-based

Memory science splits prospective memory in two; a stored item is an intention.

kindcue--whenstoreddue
time-baseda day arrivestoday, tomorrow, a weekday (the next one after today), YYYY-MM-DD, +3d, +2wdue: <date>, resolved once, from the local todayon and after that date
event-basedsomething happensany other words: after grove ships, verbatim, a malformed date's tooafter: <the words>always listed, marked waiting: no date tells when an event happened

The local today is date +%F, which reads the machine's time zone ($TZ, else /etc/localtime), so "tomorrow" said at 11 pm is the owner's tomorrow, not UTC's. No crate needed; the date arithmetic is the calendar's own (days since the epoch, the day held to a round trip).

The verbs

Plain words on the CLI; the same four as MCP tools.

  • defer — sandman defer "<what>" --when <when> [--about <path>] [--session <uuid>] writes one intention and prints <id> <date> or <id> waiting: <event>. A missing what or when is refused, exit 2: a deferral without a when is a todo, which this is not. --id <id> --when <when> pushes one to a new when and reopens it.
  • due — sandman due [--all]: the open ones due by today, most overdue first, then every one waiting on an event; --all adds the upcoming by date. One row each: id, date or waiting: <event>, what, and the repository when --about named one; nothing due without a row.
  • done, drop — sandman done <id> [--note "<text>"] closes one as finished, drop as no longer wanted. An id is matched by its start; one that matches none or several is one stderr line, exit 1.
  • ledger — one line each through mark's writer, kind defer, push, done or drop, with id, the due or after a defer or push set, the note, the session.

Nothing expires or closes on its own: an intention stays open until the person's session closes it.

The store

One file an intention, the memory file's shape; disk is the truth, nothing is cached.

<root>/intentions/0a1b2c3d.md
---
due: 2026-11-03                  or  after: after grove ships
created: 2026-11-02T09:00:00Z
about: /work/alpha               the repository, when given
session: 5a000000-0000-4000-8000-00000000000a
graduate: 3f9a0c1d2b4e           a graduation's proposal: the note's id
artifact: /work/alpha/AGENTS.md  and where it would go
state: open                      open, done or dropped
closed: …                        once closed
note: …                          the close's note
---

sample: rerun the alpha bench on the new box

The body is what was deferred, in the person's words. A push rewrites due or after in place; a close sets state and closed. The weekly review writes one per graduation it proposes (the ladder); done on it ends its note into the artifact. Recall never reads intentions/: an intention is surfaced by date, not ranked by relevance. sandman chart lists every one under intentions (id, what, due or after, state, created, closed, about, session) for a timeline to draw.

What the seed shows

After the instructions, before the always-set, counted against the seed's budget as a fixed part; absent when nothing is due.

The seed's instructions gain one sentence: when the person defers work (later, tomorrow, after X), run sandman defer "<their words>" --when <when> at once, and close it with sandman done <id> once finished. The block is sandman due's own output, capped at ten rows and then … <n> more: sandman due; its header carries the rule. From the suite's seed (docs/data/recall-seed.txt, pinned to the real output):

due · deferred work: raise it with the person, never start it unasked
  · 0a1b2c3d 2026-11-03 — Rerun the alpha bench on the new box (/work/alpha)
  · 6e7f8a9b 2026-11-10 — Draft the beta release notes
  · 4e5f6a7b waiting: after grove ships — Cut sandman over to the rewrite

Surfaced, never acted on

Settled 2026-11-14.

A due intention is shown to the session and raised with the person; the daemon never acts on one and never starts a session for one, and an agent never starts the work unasked. The owner: "it should be surfaced, routines run in the bg, this is generally work we do together". Work that should run unattended is a routine's, not an intention's; serve's tick has no job here.

Open questions

  • How an event-based intention is matched to a session: a lexical match on its words, the decision model as recall asks it, or the person's word alone.
  • Whether a long-waiting event crowds the seed: unmeasured; the cap of ten bounds it.
  • Recurring items are out of scope: anything that repeats on a schedule is a routine.
