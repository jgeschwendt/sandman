sandman · design

memory for agentic sessions

sandman is being rewritten from scratch, one part at a time; this build carries mark, take, chart and the daemon, serve, with its status and setup. Its memory follows complementary learning systems: a fast, temporary store captures each session as an episode, and a slow store absorbs episodes through replay.

mark

Run by the subether mod inside its 1.5 s budget, so it does nothing slow. Today it writes the start and end marks; next it carries call and prompt while recall (Next) and take take over start and end.

One JSON object on stdin; kind and session are required, any other field missing is null.

{"kind":"start"|"end","session":"<uuid>","cwd":"<path>"?,"surface":"<str>"?,"interactive":bool?,"reason":"<str>"?,"resume":"<str>"?}

It appends one compact line, keys alphabetical, to today's (UTC) ledger/<yyyy>/<mm>/<dd>.jsonl with O_APPEND, so concurrent writers interleave whole lines:

{"at":"2026-11-09T08:05:00Z","cwd":"/work/alpha","interactive":true,"kind":"start","machine":"studio","reason":"startup","resume":null,"session":"5a000000-0000-4000-8000-00000000000a","surface":"cli"}
  • exit 0 — written, silent.
  • exit 2 — stdin not JSON, or kind or session missing or invalid: one line on stderr, nothing written.
  • exit 1 — the root cannot hold the line: one line on stderr.

take

The one verb the mod runs at a session's end, inside its 1.5 s budget: nothing slow, nothing spawned. A session is marked at its start and taken at its end; one without a start mark is outside this system.

One JSON object on stdin; session is checked as in mark.

{"session":"<uuid>","cwd":"<path>"?,"reason":"<str>"?}

It decides one outcome, the first that holds, and appends one end line to today's ledger with the same writer as mark:

no start mark for the session in the ledgernothing written
reason is resume: the end fires on the session a resume adoptsnothing written

a job's state.json under <claude>/jobs/ names it, by resumeSessionId, else sessionId, and reason is not clearheld, with job
no <claude>/projects/*/<session>.jsonlgone
otherwisetaken, with archived
 
{"archived":"<path>"?,"at":…,"cwd":…,"job":"<job dir>"?,"kind":"end","machine":…,"outcome":"skipped"|"held"|"gone"|"taken","reason":…,"session":…}

<claude> is $CLAUDE_CONFIG_DIR, else $HOME/.claude. The take renames, never copies, the transcript to .archive/claude/<yyyy>/<mm>/<dd>/<HHMMSS>-projects-<project>-<session>.jsonl at the take's UTC time (<HHMMSS>-<n>-… on a same-second clash) and its sidecar dir <session>/, when there is one, to the same stem plus -dir. Then it writes memories/.recent/<session>.json atomically, keys in this order, for the earlier recall and dream to read:

{"archived":"<abs path>","cwd":str|null,"ended":"<the transcript's mtime>","title":"<str>","highlights":[…]}
  • pointer — cwd: the first transcript line's without control characters, else stdin's. title: the first user message, whitespace collapsed, cut at 80 characters, else the session id. highlights: the quoted bodies of sandman remember and orrery attend in the commands the session ran (a tool call, a ! line), one-lined, cut at 4,000 characters, the latest of a repeat kept, the last 20.
  • order — rename, pointer, ledger line: an interruption never loses a transcript, and an archive without a pointer charts as archived.
  • exit 0 — decided, silent. exit 2 — bad stdin, one stderr line, nothing written. exit 1 — a rename or write failed (cross-device included): one stderr line, no ledger line.
  • held — the daemon takes it later, see serve.

chart

One compact JSON object on stdout, keys alphabetical. It reads the root and never writes it, bar minting machine; every absence is an empty list or a skipped item, never an error.

{"active":[{"cwd":str|null,"end":str|null,"machine":str,"outcome":str|null,"session":str,"start":str|null}],
 "at":"<now, RFC 3339 UTC>",
 "machine":"<this machine's id>",
 "memories":[{"bank":str,"created":str|null,"file":str,"name":str,"session":str|null,"source":"dream"|"reflect"|"remember"|"other","type":str}],
 "taken":[{"bytes":int,"cwd":str|null,"dreamed":str|null,"highlights":int,"memories":int,"session":str,"state":"waiting"|"dreamed"|"archived","taken":str,"title":str|null}]}
  • active — one per session in the ledger files: start the at of its earliest start mark (a reload re-fires it), end and outcome of its latest end mark (an end without one: null); cwd and machine from that start mark, else the end mark. By start, then session.
  • taken — one per archived transcript, a file directly in a day dir named <HHMMSS>-…-<session>.jsonl; the latest wins when a session has several. taken is that day and time in UTC, bytes the file's size; title, cwd, highlights (a count) and dreamed come from the pointer. state: waiting, a pointer without dreamed; dreamed, with it; archived, no pointer. memories counts the memory files naming the session. By taken, then session.
  • memories — every .md directly in a bank dir but MEMORY.md, banks and files starting with . or _ skipped. name falls back to the file stem, type to ""; source is the first word of the frontmatter's when it is dream, reflect or remember, else other; a dream's session is the uuid in its source line (dream <ISO> · <uuid> · minds=…). By bank, then file.

serve

The daemon, a foreground process launchd keeps alive as dev.gigantic.sandman. Its one job is the tick that settles held takes; encoding and consolidation (Next) will run here too.

At ① it creates run/ 0700 and refuses it if it is not this user's or group or other can reach it; takes an exclusive flock on run/serve.lock, held for life; binds run/serve.new and renames it over run/serve.sock, safe because the lock proves no one else is alive; and writes run/serve.pid. Then it logs its start and prints its health line on stdout, so whoever spawned it knows it is ready without polling.

One newline-terminated JSON request and one reply per connection, compact, keys alphabetical; a connection silent for 1 s is dropped unanswered. Errors are typed codes.

{"op":"health"}   → {"machine":str,"ok":true,"pid":int,"since":"<RFC 3339 start>","state":"booting"|"ready"|"stopping","version":"<crate version>"}
{"op":"shutdown"} → {"ok":true}, written after the listener is dropped
anything else     → {"code":"bad_request"|"unknown_op","ok":false}
  • state — ready whenever it answers today: there is nothing to derive before the socket is bound, and a stopping daemon no longer accepts.
  • tick — every 30 s ($SANDMAN_TICK_MS) it re-derives from disk every session whose latest ledger line is a held end on this machine; one no job names any more, whose transcript has been untouched for 120 s ($SANDMAN_QUIET_MS), it takes as take does and ends with taken or gone, reason job gone. A take that fails is logged and stays held for the next tick.
  • signals — SIGTERM, SIGINT and SIGHUP take the shutdown path; SIGPIPE is ignored. The drain budget is 2 s, launchd's ExitTimeOut: the one connection in hand, at most its 1 s read, and the take in hand; the tick starts no other. On exit it removes serve.pid and serve.sock while the pid file still holds its pid.
  • log — run/serve.log, one compact object per line with at: start (pid, version), exit (reason: signal TERM, shutdown request, an accept error), take (the tick's end line, or its session and error as reason), panic from the panic hook. A line that finds it at $SANDMAN_LOG_CAP bytes (1 MiB) first renames it to serve.log.1.
  • status — sends health and prints the reply, exit 0, with one stderr line naming both versions and launchctl kickstart -k gui/$(id -u)/dev.gigantic.sandman when the daemon's is not the client's; no daemon prints {"code":"down","ok":false}, exit 1.
  • setup — prints the plist and writes nothing: this executable and serve, the root it ran with, KeepAlive, RunAtLoad, ThrottleInterval 10, ExitTimeOut 2, stderr to serve.err beside run/ for failures before the log.

launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.gigantic.sandman.plist

Next

Parts still to bring over.

  • consolidate: in serve, later. Consolidation stabilises a bank's traces (newly encoded memories, still labile: easy to change or lose) and integrates them with what the bank already holds: a trace that revises a memory updates it (reconsolidation), and pruning drops a trace that does not hold or a memory gone stale. It takes the place of the dream pass.
  • encode: in serve, right after a take, one episode at a time. Encoding is a headless model, Claude Opus by default (one setting, so a local model can replace it), reading the archived transcript and writing the episode's traces, each carrying its session id and archive path, to traces/<bank>/<file>.md, for the bank the session's cwd belongs to. The run is flagged so it is never itself marked, taken or encoded. Once it lands, the short-term pointer goes.
  • mark: the mod's tool log moves into the ledger, which becomes every mod event: mark writes a call line per tool call and a prompt line per typed prompt. Readers that need only sessions skip those kinds; encoding, consolidation and the end-of-day judge read a session's calls and prompts from it.
  • recall: the one verb the mod runs at a session's start. It writes the start mark first, whether or not there is anything to recall, so mark stops writing it.
