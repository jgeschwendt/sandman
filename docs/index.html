sandman · design

memory for agentic sessions

sandman is rewritten from scratch, one part at a time. This build carries mark, take, chart, forget, the agent's recall, show and remember, its defer, due, done and drop, and the daemon, serve, whose tick ends sessions that never ended, settles held takes, encodes episodes, consolidates banks and topics and reviews its own guidance weekly; status, setup, upgrade and version run it. A fast store captures each session as an episode, a slow one absorbs episodes through replay, and the memory cycle decides what holds, what ends and when a transcript goes. It runs unattended: every change is a ledger line, recoverable from .pruned/ or the prompt history; today only forget deletes for good.

mark

Run by the subether mod inside its 1.5 s budget, so it does nothing slow. Today it writes the start and end marks and a guard per tool call the mod's guard denies; next it carries call and prompt while recall (Next) and take take over start and end.

One JSON object on stdin; kind and session are required, any other field missing is null.

{"kind":"start"|"end","session":"<uuid>","cwd":"<path>"?,"surface":"<str>"?,"interactive":bool?,"reason":"<str>"?,"resume":"<str>"?}
{"kind":"guard","session":"<uuid>","rationale":"<str>","tool":"<str>"?}

It appends one compact line, keys alphabetical, to today's (UTC) ledger/<yyyy>/<mm>/<dd>.jsonl in one O_APPEND write under a shared flock, so concurrent writers interleave whole lines and forget's rewrite loses none; a guard's rationale is one-lined to 1,000 characters:

{"at":"2026-11-09T08:05:00Z","cwd":"/work/alpha","interactive":true,"kind":"start","machine":"studio","reason":"startup","resume":null,"session":"5a000000-0000-4000-8000-00000000000a","surface":"cli"}
{"at":"2026-11-09T09:10:00Z","kind":"guard","machine":"studio","rationale":"sample: never force-push","session":"5a000000-0000-4000-8000-00000000000a","tool":"Bash"}

A guard is never a session's mark: every reader of sessions (chart's active, take, reconcile, settle, encode) reads only start, end and encode lines.

exit 0 written, silent; exit 2 stdin not JSON, or kind or session missing or invalid, a guard without a string rationale: one stderr line, nothing written; exit 1 the root cannot hold the line: one stderr line.

take

The one verb the mod runs at a session's end, inside its 1.5 s budget: nothing slow, nothing spawned. A session is marked at its start and taken at its end; one without a start mark is outside this system, and the seed marks only an interactive one, so a headless claude -p run (a routine) is never taken, reconciled or encoded.

One JSON object on stdin; session is checked as in mark.

{"session":"<uuid>","cwd":"<path>"?,"reason":"<str>"?}

<claude> is $CLAUDE_CONFIG_DIR, else $HOME/.claude. The take renames, never copies, the transcript to .archive/claude/<yyyy>/<mm>/<dd>/<HHMMSS>-projects-<project>-<session>.jsonl at the take's UTC time (<HHMMSS>-<n>-… on a same-second clash) and its sidecar dir <session>/, when there is one, to the same stem plus -dir. Then it writes memories/.recent/<session>.json atomically, keys in this order, for the earlier recall and dream to read; it goes when recall (Next) replaces the earlier one:

{"archived":"<abs path>","cwd":str|null,"ended":"<the transcript's mtime>","title":"<str>","highlights":[…]}
  • pointer — cwd: the first transcript line's without control characters, else stdin's. title: the first user message, whitespace collapsed, cut at 80 characters, else the session id. highlights: the quoted bodies of sandman remember and orrery attend in the commands the session ran (a tool call, a ! line), one-lined, cut at 4,000 characters, the latest of a repeat kept, the last 20.
  • order — rename, pointer, ledger line: an interruption never loses a transcript, and an archive without a pointer charts as archived.
  • exit 0 — decided, silent. exit 2 — bad stdin, one stderr line, nothing written. exit 1 — a rename or write failed (cross-device included): one stderr line, no ledger line.
  • tick — the daemon ends sessions through the same path, see serve: a held one, reason job gone; one that never ended, no end recorded (gone) or idle (taken).

 "knowledge":[{"created":str|null,"file":str,"name":str,"session":str|null,"sessions":[str],"source":…,"topic":str,"type":str}],

 "traces":[{"bank":str,"created":str|null,"file":str,"name":str,"session":str|null,"sessions":[str],"type":str}]}
  • active — one per session in the ledger files: start the at of its earliest start mark (a reload re-fires it), end and outcome of its latest end mark (an end without one: null), both null when a start mark is later (resumed, running again); cwd and machine from that start mark, else the end mark; encoded the outcome of its latest encode line; interactive true when a start mark says so, else false when one says false, else null; seen the live transcript's mtime, null without one. By start, then session.
  • guards — one per guard line in the ledger, by at: the denied tool calls bifrost's portals page lists.
  • taken — one per archived transcript, a file directly in a day dir named <HHMMSS>-…-<session>.jsonl; the latest wins when a session has several. taken is that day and time in UTC, bytes the file's size; title, cwd, highlights (a count) and dreamed come from the pointer. state: waiting, a pointer without dreamed; dreamed, with it; archived, no pointer. memories counts the memories and knowledge pages whose sessions holds the session. By taken, then session.
  • memories — every .md directly in a bank dir but MEMORY.md, banks and files starting with . or _ skipped. name falls back to the file stem, type to ""; source is the first word of the frontmatter's when it is consolidate, dream, reflect or remember, else other; a consolidate's or a dream's session is the uuid in its source line (dream <ISO> · <uuid> · minds=…); sessions is the note's provenance, every archived session it descends from, sorted, once each: the uuids on its sessions: line (space-separated, directly before source:), its session: and that session. By bank, then file.
  • intentions — every intentions/<id>.md, open and closed, its frontmatter as it stands and what its body (the store). By created, then id.
  • knowledge — every page under knowledge/<topic>/, read as memories are, topic in place of bank. By topic, then file.
  • traces — every trace file, read and skipped as memories are, a topic's bank @<topic>; session from its frontmatter, sessions as a memory's. By bank, then file.

forget

The privacy ending, and the one verb that deletes for good: no .pruned/ copy, and nothing recorded that names the session. The /delete skill and bridge's forget button run it twice.

  • today's file — every append (mark, take, recall, the tick, the daemon's log, the embedding cache) is one O_APPEND write under a shared flock; forget holds the exclusive one while it reads, writes the temp file and renames it over. An append in flight finishes first; one waiting on the old file wakes holding an inode no longer at the path, sees so, and opens the replacement. The suite races 90 marks against 20 rewrites and loses none; without the lock, 4 runs of 5 lost 4 or 5 (measured 2026-11-14). A CLI cannot take the daemon's tick lock, and needs none: the lock is on the file.
  • what stays — what a consolidate already merged into another memory: a merge cannot be unpicked, so only what session: attributes is removed, and the stamp naming the session is rewritten. Claude Code's own stores (history.jsonl, file-history/, session-env/) are not sandman's; neither are the old sandman's directories (data root). An encode in flight may still write its traces and line; the second run takes them.
  • exit — 0, idempotent: nothing to forget once all is gone; 2 on an id that is not a session's; 1 on a failed removal or write, one stderr line, the rest left for the next run.

serve

The daemon, a foreground process launchd keeps alive as dev.gigantic.sandman. Its tick runs six jobs, in order: it reconciles sessions that never ended, fills recall's embedding cache, settles held takes, then one of: a rollback due, encode one episode, consolidate one bank, or, with neither waiting, once a week, reflect on the guidance.

At ① it creates run/ 0700 and refuses it if it is not this user's or group or other can reach it; takes an exclusive flock on run/serve.lock, held for life; binds run/serve.new and renames it over run/serve.sock, safe because the lock proves no one else is alive; and writes run/serve.pid. Then it logs its start and prints its health line on stdout, so whoever spawned it knows it is ready without polling.

One newline-terminated JSON request and one reply per connection, compact, keys alphabetical; a connection silent for 1 s is dropped unanswered. Errors are typed codes.

{"op":"health"}   → {"machine":str,"ok":true,"pid":int,"since":"<RFC 3339 start>","state":"booting"|"ready"|"stopping","version":"<release>-<build>"}
{"op":"shutdown"} → {"ok":true}, written after the listener is dropped
anything else     → {"code":"bad_request"|"unknown_op","ok":false}
  • state — ready whenever it answers today: there is nothing to derive before the socket is bound, and a stopping daemon no longer accepts.
  • reconcile — every 30 s ($SANDMAN_TICK_MS), from disk, first: a session of this machine whose latest start mark is later than its latest end, or that has none, older than 10 min ($SANDMAN_GRACE_MS; its transcript may not exist yet), no unfinished job naming it: without a live transcript it ends gone, reason no end recorded (a crash, a kill, a session from before take), at most 20 a tick; with one untouched for a week ($SANDMAN_IDLE_MS) it is taken as take does, reason idle, one a tick, so an abandoned session's memory is kept; otherwise it may be alive and is left. A session resumed later gets a new start mark and is open again.
  • embed — the cache rewritten to its live lines once it passes twice their size, then every candidate recall would embed and the cache lacks, in reader order, at most 128 a tick ($SANDMAN_EMBED_TICK), 16 a request to $SANDMAN_OLLAMA; a first build of 635 takes about 22 s of an idle Ollama, so it lands over a few ticks. A stop kills the request in hand.
  • settle — a session whose latest end is held on this machine with no start since, no unfinished job naming it any more, its transcript untouched for 120 s ($SANDMAN_QUIET_MS), is taken as take does: taken or gone, reason job gone. A take that fails is logged and stays held for the next tick.
  • signals — SIGTERM, SIGINT and SIGHUP take the shutdown path; SIGPIPE is ignored. The drain budget is 2 s, launchd's ExitTimeOut: the one connection in hand, at most its 1 s read, and the tick's job in hand (a running model command is killed); the tick starts no other. On exit it removes serve.pid and serve.sock while the pid file still holds its pid.
  • log — run/serve.log, one compact object per line with at: start (pid, version), exit (reason: signal TERM, shutdown request, an accept error), embed (embedded, or the failure as reason), reconcile, take, encode, consolidate and reflect (the tick's ledger line, or its session, bank or kind and the write's error as reason), panic from the panic hook. A line that finds it at $SANDMAN_LOG_CAP bytes (1 MiB) first renames it to serve.log.1.
  • version — sandman version prints <release>-<build>: the YYYY.M.N the release workflow stamps (a checkout's build: the crate version), then the commit it was built from (-dirty over uncommitted work), the same string health carries: an installer's smoke check.
  • status — sends health and prints the reply, exit 0, with one stderr line naming both versions and the fix, sandman setup, when the daemon's is not the client's; no daemon prints {"code":"down","ok":false}, exit 1.
  • setup — installs the release and the agent. First it boots out the old sandman's agents (dev.gigantic.sandman.breathe, .reflect, .report) and removes their plists; then hotswap's ensure brings the release into its layout (~/.local/share/hotswap/sandman/<version>/: a mise install of a newer version moved in, else, with none active, the latest release installed through packslip under the signer ps1_nensfiggtc7n6uctbniwf7q4am), links ~/.local/bin/sandman through its current and owns the upgrade agent, dev.gigantic.sandman.upgrade (sandman upgrade every 900 s), which setup never writes, loads or boots out. The daemon's plist runs that link, never the executable that ran setup, so a checkout's setup wires the installed release: the link and serve, the root it ran with and the caller's PATH (launchd's finds no claude), KeepAlive, RunAtLoad, ThrottleInterval 10, ExitTimeOut 2, stderr to serve.err beside run/ for failures before the log; --print prints it and writes nothing. setup writes ~/Library/LaunchAgents/dev.gigantic.sandman.plist by temp + rename, then kickstarts it when that plist was already loaded and loads it afresh otherwise. After a bootout it polls launchctl print until the job is gone (at most $SANDMAN_BOOTOUT_MS, 30 s): a bootstrap before then fails. Without launchctl (Linux) it stops before writing anything; --remove has hotswap forget the upgrade agent, the layout and its record, then boots the daemon out and removes its plist and the link, leaving the root alone.
  • upgrade — sandman upgrade [--check | --back | --retry] is hotswap's swap under sandman's manifest, its exit code hotswap's (0 green or settled, 1 red, 2 unable to try). A release is newer when releases/latest names a newer tag; packslip installs it beside the running version, current moves, then sandman setup, one kickstart -k of dev.gigantic.sandman and the smoke: sandman version, then sandman status once a second until the restarted daemon answers with that same version, 30 s at most. A failed step rolls back to the previous version and holds the red one off until a newer release. No drain step: the kickstart's SIGTERM is the daemon's own 2 s drain, and a separate stop would race KeepAlive's respawn. Releases come from .github/workflows/release.yaml, one per merge to main, YYYY.M.N, for aarch64-apple-darwin and x86_64-unknown-linux-gnu, signed by packslip.

encode

A job of serve's tick, not a verb: one episode, a taken session, at a time, written as traces, newly encoded memories still labile, under traces/<bank>/, apart from the banks until consolidate.

Each tick, after settling, it derives from the ledger the oldest session of this machine whose latest end is taken, with no start or encode since, decides one outcome, and appends one line with mark's writer:

whenoutcome
no start mark of the session says interactive true: a start marked by mark alone, since the seed never marks a headless runskipped, no model call
no file at the end line's archivedgone
the encoder exits non-zero, outlives $SANDMAN_ENCODE_MS (300 000), or prints no valid objectfailed, with error; no trace written
otherwiseencoded; traces counts them, often 0
 
{"at":…,"error":"<one line>"?,"kind":"encode","machine":…,"outcome":"encoded"|"skipped"|"gone"|"failed","session":…,"token":…?,"traces":<count>}
  • digest — what the model reads, built from the archive: # episode (the take's time, the cwd as the pointer finds it), # already remembered (what the session saved with remember, one name and description each, which the contract says never to write again), # highlights (take's, those no remembered note already holds word for word), # transcript: a user: or assistant: line per message text and a tool: line per tool call (its name and command or file, 200 characters); tool results dropped. Over $SANDMAN_DIGEST_BYTES (300 000) it keeps the head and the tail, whole lines, and the middle becomes … <n> bytes omitted ….
  • model run — shared by both jobs: $SANDMAN_ENCODER here, a command line run by sh -c in its own process group with CLAUDE_MEMORY_PIPELINE=1 and SANDMAN_NO_TAKE=1, so a session it starts is never taken; by default a headless Claude Opus with no tools, no hooks, MCP servers or CLAUDE.md, and no saved session: claude -p --model opus --output-format text --safe-mode --tools "" --no-session-persistence. Its stdin is the guidance, the contract and the data; its stdout one object, text around it ignored; exit 0.
  • sign-in — the stored interactive login expires; a token file outlives it, a year. Read at each run, so a replaced file needs no restart: $SANDMAN_CLAUDE_TOKEN_FILE, else ~/Codes/claude-oauth-token, a regular file no group or other can read, its trimmed text set as CLAUDE_CODE_OAUTH_TOKEN for the command alone. The line's token says which, never the value: absent without the file (the stored login, as before), the path when used, refused: <path>: mode <octal>, want a regular file of mode 600 or ignored: <path> is empty, the run going ahead without it.
  • prompt — two parts. The contract (src/prompts/encode.contract.md) fixes the input layout and the reply's shape; it is built in and always sent, so no edit can break parsing. The guidance, what a trace is and how to word one, is <root>/prompts/encode.md when that file holds any text, else the built-in default (src/prompts/encode.md), so it changes without a rebuild. A local model replaces Opus with any command that keeps the contract: 
    {"traces":[{"type":"user"|"feedback"|"project"|"reference"|"knowledge"|"playbook","name":str,"description":str,"body":str,"about":str|null,"topic":str|null}]}
  • homing — sessions start from one root directory and dispatch work into many repositories, so a session's cwd says little about what a fact concerns. A knowledge or playbook trace names its topic, a slug (lowercase letters, digits, -), and lands in traces/@<topic>/ (the knowledge store); a type without one fails the episode. Any other trace names its repository in about; the bank is that directory's key when it is an absolute path to an existing directory, else the episode cwd's, else $HOME's. A key is the earlier sandman's: the directory a linked worktree sits in, the checkout a nested worktree belongs to, else the directory itself, every byte not alphanumeric -. The trace lands at traces/<bank>/<type>_<slug>.md by temp file and rename, the slug the bank format's (the name lowercased, non-alphanumeric runs _, 60 characters), _2, _3 on a clash.
  • stop — a stop signal or shutdown request kills the model's group and writes no line, so the job runs again after the next start. failed is final: the tick never retries it; removing its line from the ledger does.

consolidate

A job of serve's tick: it stabilises a bank's traces and integrates them with what the bank holds. A trace that revises a memory updates it (reconsolidation); pruning drops a trace that does not hold or a memory gone stale. Nothing waits for a person. The cycle adds memory-to-memory ops (not built).

It runs only in a tick with no episode to encode, one bank at a time, derived from disk each tick: of the banks under traces/, a topic's @<topic> among them, whose newest trace's created is older than $SANDMAN_CONSOLIDATE_QUIET_MS (600 000, so a burst of episodes lands first), the one with the oldest trace. A bank whose last consolidate failed waits for a trace newer than the failure, so a bad reply never storms. The model run is encode's, with $SANDMAN_CONSOLIDATOR and $SANDMAN_CONSOLIDATE_MS (600 000), its guidance <root>/prompts/consolidate.md else the default, then its contract (src/prompts/consolidate.contract.md), then the bank. A topic's runs the same way with knowledge/<topic>/ in place of memories/<bank>/, and its keeps take knowledge or playbook only (how a page is written):

# bank

<trace file="feedback_clock_in_benchmarks_too.md">
…the whole file…

…the whole file…

Memories go whole while their bytes fit $SANDMAN_CONSOLIDATE_BYTES (300 000); the rest are listed, and the contract says a listed memory may not be changed. The reply is {"ops":[…]}:

{"op":"keep","trace","type","name","description","body"}the trace becomes a memorymemories/<bank>/<type>_<slug>.md, encode's slug and clash; created, about, topic, session, archived from the trace

  • checked — every trace named by exactly one op, every file named present in the input, a memory named at most once and never a listed one; otherwise the whole reply is rejected and nothing changes.
  • applied — every write staged beside its target first (a failure removes them and fails); then every named trace, and every merged or pruned memory as it stood, renamed to .pruned/<yyyy>/<mm>/<dd>/<HHMMSS>-<bank>-<file> beside the reply, …-<bank>-ops.json, reasons included; then the writes renamed in. Nothing is deleted.
  • stamped — a kept or merged memory's source is consolidate <now> · <the trace's session> · model=<model>; a merge replaces the earlier one, which .pruned/ keeps. A keep or a merge is the note continuing (the note): its sessions: line, directly before source:, is the union of the trace's and the memory's, so the sessions it descends from outlive the stamp it replaces. MEMORY.md is left alone: the earlier recall reads memory files, never the index, and the earlier commit path regenerates it whole.
  • stop — as encode's: no line, the bank runs again after the next start.

reflect

A job of serve's tick, the weekly review: the pipeline rewrites the guidance encode and consolidate run on from evidence of what they did, and adopts a rewrite only when a replay judges it no worse. No step waits for a person; the contracts stay fixed in the binary.

It runs only in a tick with no rollback due, no episode waiting and no quiet bank; at most once per $SANDMAN_REFLECT_MS (604 800 000, a week) after this machine's latest reflect line, and only when at least $SANDMAN_REFLECT_MIN (5) encode or consolidate model runs follow it: no evidence, no run and no line. The memory cycle

A session's transcript is encoded into traces, consolidated into memories and knowledge pages, sent by recall, judged, counted, then revised, merged, graduated or decayed; once no active note names the session, its transcript goes. Text and Rust, no database: every fact here is a file or a ledger line, and any index is a cache rebuilt from them.

Built: the trail inward (session → archive → trace → note, each note naming its sessions on sessions:), recall's and show's ledger lines, consolidate's trace ops. Not built: the rest of this section, in the stages under next.

The note

Every memory, knowledge page and trace keeps the file format it has today, with three keys added and one forbidden; writers put id first, from and origin just before sessions:

---
id: 3f9a0c1d2b4e                 12 lowercase hex from /dev/urandom, minted once, never changed
name … archived                  as today
from: 0a1b2c3d4e5f 9e8d7c6b5a4f  the notes it was merged from, sorted; only on a note a merge created
origin: import|routine|hand      only on a note with neither sessions nor from
sessions: <uuid> <uuid>          the archived sessions it descends from, sorted (built)
source: <stamp>                  as today
updated: <now>                   as today
---
  • source — no writer produces a note without one: sessions (chart's, from sessions:, session: and the stamp), from:, or origin:; never - or an empty value. remember without --session writes origin: hand.
  • continuing — a keep (the trace's id), a trace merged in, a revise, a retitle and a rehome are the same note: the id stays, sessions: and from: gain what it absorbed.
  • new — a merge of two or more notes, and a rung-1 graduation, write a new id, from: the parents, and no sessions:, session: or archived:: it starts clean. The parents end; their sessions stay on the rewrite line that ended them.
  • end — merged into a new note, graduated, or pruned (by consolidate, or by decay); nothing else ends a note. forget is no end: it erases.
  • strength — counted from the ledger, never stored; check refuses a strength: key.

The rewrite line and lineage

One ledger line per note rewritten, through mark's writer, never edited; recall's sent entries and the show, remember and encode lines gain id, and a path in an older line resolves through these lines' paths:

 "model":"<model>"|null,"op":"keep"|"merge"|"revise"|"retitle"|"rehome"|"graduate"|"prune"|"release"|"revert",

  • depth 1 — .pruned/ keeps each active note's direct parents and its own previous version, what a rollback needs; when a note ends, its parents' bodies are deleted. A pruned note's body stays $SANDMAN_RELEASE_DAYS. A file the next weekly review reads (written after the latest reflect line, or among the latest $SANDMAN_REFLECT_REPLAY replies and the copies they name) stays until it is not. Older generations are rewrite lines only.
  • order — each consolidate and weekly review line carries "order":{"after":{"chars","eval"?,"notes"},"before":{…},"merges":n} over the bank's, the topic's or the store's active notes. A pass with an order op (a merge of notes, a graduation, a note pruned) that lowers neither notes nor characters nor raises the recall evaluation's score, or that lowers the score, is reverted: its copies back from .pruned/, its writes removed, revert lines, outcome reverted. A trace's intake and a verdict's revise are never reverted for order.

Strength and decay

strength = (1 + 3·used + 1·shown − 4·judged) × 2^(−idle ÷ 30)
  • terms — over the note's id: used its used verdicts, shown its show lines, judged its wrong and stale verdicts since its body last changed (a revise or a merge clears them), idle the days since the latest of its created, updated, used verdicts and shows. $SANDMAN_USED_WEIGHT (3), $SANDMAN_SHOWN_WEIGHT (1), $SANDMAN_JUDGED_WEIGHT (4), $SANDMAN_HALF_LIFE_DAYS (30).
  • floor — $SANDMAN_DECAY_FLOOR (0.1): a note never used reaches it after 100 days idle (30 · log₂ 10), shown once 130, used once 160, used five times 220.
  • decay — the weekly review prunes, with no model run, each active note under the floor but a type: user note, a recall: pin or mute one, one with a judged verdict outstanding (consolidate's to revise or prune), and a trace (consolidate's).

Graduation

  • rung 1 — consolidate's reply op graduate (below) writes a trace under traces/@<topic>/, a new id, from: the memories, which end; the topic's consolidate keeps it as a page or merges it into one, the page continuing with its from: extended. A bank's input gains # elsewhere: at most 5 notes of other banks and topics whose cached embedding has cosine at least $SANDMAN_NEAR (0.8) with a trace or memory sent, listed and never written, so a subject converging across banks shows.
  • rung 2 — the weekly review's evidence gains # standing: a note with used verdicts in $SANDMAN_GUIDE_SESSIONS (5) distinct sessions and no wrong or stale ever. Its reply gains propose (below), the artifact the most specific one (a repository's AGENTS.md, a rules file, a skill, CLAUDE.md); a rung-2 proposal with no replaces justifies its characters in why or is dropped.
  • rung 3 — # relearned: a note, or the line it graduated into, that traces of $SANDMAN_MECHANISM_SESSIONS (3) distinct sessions merged into since it was written: the same failure needed the lesson again. Proposed as a hook, lint, test, gate or tool default.
  • approval — each proposal becomes an intention, due today, about the artifact's repository, graduate: <note id>, which the seed surfaces. The owner has it applied; done on it ends the note (graduate, to the artifact); drop declines, and the note is not proposed again until its body changes.

Release

  • held — a transcript while its session waits for encode, or an active note or a trace names it (chart's sessions). Unheld since the latest of its take, its encode line and the rewrite line that ended the last note naming it.
  • released — a tick job after settle, at most $SANDMAN_RELEASE_TICK (20) a tick: unheld for $SANDMAN_RELEASE_DAYS (7), its archived file, -dir and .recent pointer are deleted and a release line written; the id stays in the ledger and on ended notes' lines. The same job sweeps .pruned/ to depth 1. It runs only while sandman check passes, so a broken link never frees a transcript.

check

sandman check            # every violation, or check: <n> notes, <n> held, <n> released: clean
sandman check --fix      # what can be repaired mechanically, then check
sandman check --release  # what the release job would delete now, with its bytes; writes nothing
  1. every note has id:, 12 lowercase hex, unique across memories, knowledge and traces;
  2. every note has a source (sessions, from: or origin: import|routine|hand), and none of those keys is - or empty;
  3. sessions: holds uuids, from: ids, each sorted and once; no note has strength:;
  4. every from: id was ended by a rewrite line, and no active note's id was;
  5. every rewrite line has the shape above, an id ends at most once, and every to id is active or ended by a later line;
  6. .pruned/ holds no body past depth 1 and its grace;
  7. no released transcript is on disk, and none an active note names is released.

A violation is one stdout line, <path>: <invariant n>: <detail>, and exit 1. --fix mints missing ids, gives a sourceless note origin by its stamp's first word (remember → hand; consolidate, dream, reconsolidate, reflect → routine; none → import), sorts and dedupes the two lists, each by temp + rename, and writes {"at","fixed":n,"kind":"check","machine"}.
