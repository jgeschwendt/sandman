sandman · design

memory for agentic sessions

sandman is being rewritten from scratch, one part at a time; this build carries mark, take, chart, forget, the agent's recall, show and remember, its defer, due, done and drop for work put off until later, and the daemon, serve, which ends sessions that never ended, settles held takes, encodes episodes, consolidates banks and topics and reviews its own guidance weekly, with its status, setup and version. Its memory follows complementary learning systems: a fast, temporary store captures each session as an episode, and a slow store absorbs episodes through replay. The pipeline runs unattended: it may edit the memories and its own guidance, and every change is recorded in the ledger and recoverable from .pruned/ or the prompt history; only forget deletes for good.

mark

Run by the subether mod inside its 1.5 s budget, so it does nothing slow. Today it writes the start and end marks and a guard per tool call the mod's guard denies; next it carries call and prompt while recall (Next) and take take over start and end.

One JSON object on stdin; kind and session are required, any other field missing is null.

{"kind":"start"|"end","session":"<uuid>","cwd":"<path>"?,"surface":"<str>"?,"interactive":bool?,"reason":"<str>"?,"resume":"<str>"?}
{"kind":"guard","session":"<uuid>","rationale":"<str>","tool":"<str>"?}

It appends one compact line, keys alphabetical, to today's (UTC) ledger/<yyyy>/<mm>/<dd>.jsonl in one O_APPEND write under a shared flock, so concurrent writers interleave whole lines and forget's rewrite loses none; a guard's rationale is one-lined to 1,000 characters:

{"at":"2026-11-09T08:05:00Z","cwd":"/work/alpha","interactive":true,"kind":"start","machine":"studio","reason":"startup","resume":null,"session":"5a000000-0000-4000-8000-00000000000a","surface":"cli"}
{"at":"2026-11-09T09:10:00Z","kind":"guard","machine":"studio","rationale":"sample: never force-push","session":"5a000000-0000-4000-8000-00000000000a","tool":"Bash"}

A guard is never a session's mark: every reader of sessions (chart's active, take, reconcile, settle, encode) reads only start, end and encode lines.

exit 0 written, silent; exit 2 stdin not JSON, or kind or session missing or invalid, a guard without a string rationale: one stderr line, nothing written; exit 1 the root cannot hold the line: one stderr line.

take

The one verb the mod runs at a session's end, inside its 1.5 s budget: nothing slow, nothing spawned. A session is marked at its start and taken at its end; one without a start mark is outside this system, and the seed marks only an interactive one, so a headless claude -p run (a routine) is never taken, reconciled or encoded.

One JSON object on stdin; session is checked as in mark.

{"session":"<uuid>","cwd":"<path>"?,"reason":"<str>"?}

It decides one outcome, the first that holds, and appends one end line to today's ledger with the same writer as mark:

<claude> is $CLAUDE_CONFIG_DIR, else $HOME/.claude. The take renames, never copies, the transcript to .archive/claude/<yyyy>/<mm>/<dd>/<HHMMSS>-projects-<project>-<session>.jsonl at the take's UTC time (<HHMMSS>-<n>-… on a same-second clash) and its sidecar dir <session>/, when there is one, to the same stem plus -dir. Then it writes memories/.recent/<session>.json atomically, keys in this order, for the earlier recall and dream to read; it goes when recall (Next) replaces the earlier one:

{"archived":"<abs path>","cwd":str|null,"ended":"<the transcript's mtime>","title":"<str>","highlights":[…]}
  • pointer — cwd: the first transcript line's without control characters, else stdin's. title: the first user message, whitespace collapsed, cut at 80 characters, else the session id. highlights: the quoted bodies of sandman remember and orrery attend in the commands the session ran (a tool call, a ! line), one-lined, cut at 4,000 characters, the latest of a repeat kept, the last 20.
  • order — rename, pointer, ledger line: an interruption never loses a transcript, and an archive without a pointer charts as archived.
  • exit 0 — decided, silent. exit 2 — bad stdin, one stderr line, nothing written. exit 1 — a rename or write failed (cross-device included): one stderr line, no ledger line.
  • tick — the daemon ends sessions through the same path, see serve: a held one, reason job gone; one that never ended, no end recorded (gone) or idle (taken).

chart

One compact JSON object on stdout, keys alphabetical. It reads the root and never writes it, bar minting machine; every absence is an empty list or a skipped item, never an error.

{"active":[{"cwd":str|null,"encoded":str|null,"end":str|null,"interactive":bool|null,"machine":str,"outcome":str|null,"seen":str|null,"session":str,"start":str|null}],

 "guards":[{"at":str,"rationale":str,"session":str,"tool":str|null}],
 "intentions":[{"about":str|null,"after":str|null,"closed":str|null,"created":str|null,"due":str|null,"id":str,"session":str|null,"state":str|null,"what":str}],
 "knowledge":[{"created":str|null,"file":str,"name":str,"session":str|null,"source":…,"topic":str,"type":str}],

  • active — one per session in the ledger files: start the at of its earliest start mark (a reload re-fires it), end and outcome of its latest end mark (an end without one: null), both null when a start mark is later (resumed, running again); cwd and machine from that start mark, else the end mark; encoded the outcome of its latest encode line; interactive true when a start mark says so, else false when one says false, else null; seen the live transcript's mtime, null without one. By start, then session.
  • guards — one per guard line in the ledger, by at: the denied tool calls bifrost's portals page lists.
  • taken — one per archived transcript, a file directly in a day dir named <HHMMSS>-…-<session>.jsonl; the latest wins when a session has several. taken is that day and time in UTC, bytes the file's size; title, cwd, highlights (a count) and dreamed come from the pointer. state: waiting, a pointer without dreamed; dreamed, with it; archived, no pointer. memories counts the memory files naming the session. By taken, then session.
  • memories — every .md directly in a bank dir but MEMORY.md, banks and files starting with . or _ skipped. name falls back to the file stem, type to ""; source is the first word of the frontmatter's when it is consolidate, dream, reflect or remember, else other; a consolidate's or a dream's session is the uuid in its source line (dream <ISO> · <uuid> · minds=…). By bank, then file.
  • intentions — every intentions/<id>.md, open and closed, its frontmatter as it stands and what its body (the store). By created, then id.
  • knowledge — every page under knowledge/<topic>/, read as memories are, topic in place of bank. By topic, then file.
  • traces — every trace file, read and skipped as memories are, a topic's bank @<topic>; session from its frontmatter. By bank, then file.

forget

The privacy ending, and the one verb that deletes for good: no .pruned/ copy, and nothing recorded that names the session. The /delete skill and bridge's forget button run it twice.

  • today's file — every append (mark, take, recall, the tick, the daemon's log, the embedding cache) is one O_APPEND write under a shared flock; forget holds the exclusive one while it reads, writes the temp file and renames it over. An append in flight finishes first; one waiting on the old file wakes holding an inode no longer at the path, sees so, and opens the replacement. The suite races 90 marks against 20 rewrites and loses none; without the lock, 4 runs of 5 lost 4 or 5 (measured 2026-11-14). A CLI cannot take the daemon's tick lock, and needs none: the lock is on the file.
  • what stays — what a consolidate already merged into another memory: a merge cannot be unpicked, so only what session: attributes is removed, and the stamp naming the session is rewritten. Claude Code's own stores (history.jsonl, file-history/, session-env/) are not sandman's; neither are the old sandman's directories (data root). An encode in flight may still write its traces and line; the second run takes them.
  • exit — 0, idempotent: nothing to forget once all is gone; 2 on an id that is not a session's; 1 on a failed removal or write, one stderr line, the rest left for the next run.

serve

The daemon, a foreground process launchd keeps alive as dev.gigantic.sandman. Its tick runs six jobs, in order: it reconciles sessions that never ended, fills recall's embedding cache, settles held takes, then one of: a rollback due, encode one episode, consolidate one bank, or, with neither waiting, once a week, reflect on the guidance.

At ① it creates run/ 0700 and refuses it if it is not this user's or group or other can reach it; takes an exclusive flock on run/serve.lock, held for life; binds run/serve.new and renames it over run/serve.sock, safe because the lock proves no one else is alive; and writes run/serve.pid. Then it logs its start and prints its health line on stdout, so whoever spawned it knows it is ready without polling.

One newline-terminated JSON request and one reply per connection, compact, keys alphabetical; a connection silent for 1 s is dropped unanswered. Errors are typed codes.

{"op":"health"}   → {"machine":str,"ok":true,"pid":int,"since":"<RFC 3339 start>","state":"booting"|"ready"|"stopping","version":"<crate version>-<build>"}
{"op":"shutdown"} → {"ok":true}, written after the listener is dropped
anything else     → {"code":"bad_request"|"unknown_op","ok":false}
  • state — ready whenever it answers today: there is nothing to derive before the socket is bound, and a stopping daemon no longer accepts.
  • reconcile — every 30 s ($SANDMAN_TICK_MS), from disk, first: a session of this machine whose latest start mark is later than its latest end, or that has none, older than 10 min ($SANDMAN_GRACE_MS; its transcript may not exist yet), no job naming it: without a live transcript it ends gone, reason no end recorded (a crash, a kill, a session from before take), at most 20 a tick; with one untouched for a week ($SANDMAN_IDLE_MS) it is taken as take does, reason idle, one a tick, so an abandoned session's memory is kept; otherwise it may be alive and is left. A session resumed later gets a new start mark and is open again.
  • embed — the cache rewritten to its live lines once it passes twice their size, then every candidate recall would embed and the cache lacks, in reader order, at most 128 a tick ($SANDMAN_EMBED_TICK), 16 a request to $SANDMAN_OLLAMA; a first build of 635 takes about 22 s of an idle Ollama, so it lands over a few ticks. A stop kills the request in hand.
  • settle — a session whose latest end is held on this machine with no start since, no job naming it any more, its transcript untouched for 120 s ($SANDMAN_QUIET_MS), is taken as take does: taken or gone, reason job gone. A take that fails is logged and stays held for the next tick.
  • signals — SIGTERM, SIGINT and SIGHUP take the shutdown path; SIGPIPE is ignored. The drain budget is 2 s, launchd's ExitTimeOut: the one connection in hand, at most its 1 s read, and the tick's job in hand (a running model command is killed); the tick starts no other. On exit it removes serve.pid and serve.sock while the pid file still holds its pid.
  • log — run/serve.log, one compact object per line with at: start (pid, version), exit (reason: signal TERM, shutdown request, an accept error), embed (embedded, or the failure as reason), reconcile, take, encode, consolidate and reflect (the tick's ledger line, or its session, bank or kind and the write's error as reason), panic from the panic hook. A line that finds it at $SANDMAN_LOG_CAP bytes (1 MiB) first renames it to serve.log.1.
  • version — sandman version prints <crate version>-<build>, the build the commit it was built from (-dirty over uncommitted work), the same string health carries: an installer's smoke check.
  • status — sends health and prints the reply, exit 0, with one stderr line naming both versions and the fix, sandman setup, when the daemon's is not the client's; no daemon prints {"code":"down","ok":false}, exit 1.
  • setup — installs the agent. The plist: this executable and serve, the root it ran with and the caller's PATH (launchd's finds no claude), KeepAlive, RunAtLoad, ThrottleInterval 10, ExitTimeOut 2, stderr to serve.err beside run/ for failures before the log; --print prints it and writes nothing. setup boots out the old sandman's agents (dev.gigantic.sandman.breathe, .reflect, .report, .upgrade) and removes their plists, writes ~/Library/LaunchAgents/dev.gigantic.sandman.plist by temp + rename, then kickstarts it when that plist was already loaded and loads it afresh otherwise. After a bootout it polls launchctl print until the job is gone (at most $SANDMAN_BOOTOUT_MS, 30 s): a bootstrap before then fails. Without launchctl (Linux) it stops before writing anything; --remove boots the agent out and removes its plist.
mise run install && sandman-next setup   # install, retire the old agents, load or swap
sandman-next status                      # the daemon's health, its version this build's
claude setup-token                                          # in a terminal: prints a year's token, stores nothing
install -m 600 /dev/stdin ~/Codes/claude-oauth-token        # paste it, then Ctrl-D

encode

A job of serve's tick, not a verb: one episode, a taken session, at a time, written as traces, newly encoded memories still labile, under traces/<bank>/, apart from the banks until consolidate.

Each tick, after settling, it derives from the ledger the oldest session of this machine whose latest end is taken, with no start or encode since, decides one outcome, and appends one line with mark's writer:

whenoutcome
no start mark of the session says interactive true: a start marked by mark alone, since the seed never marks a headless runskipped, no model call
no file at the end line's archivedgone
the encoder exits non-zero, outlives $SANDMAN_ENCODE_MS (300 000), or prints no valid objectfailed, with error; no trace written
otherwiseencoded; traces counts them, often 0
 
{"at":…,"error":"<one line>"?,"kind":"encode","machine":…,"outcome":"encoded"|"skipped"|"gone"|"failed","session":…,"token":…?,"traces":<count>}
  • digest — what the model reads, built from the archive: # episode (the take's time, the cwd as the pointer finds it), # already remembered (what the session saved with remember, one name and description each, which the contract says never to write again), # highlights (take's, those no remembered note already holds word for word), # transcript: a user: or assistant: line per message text and a tool: line per tool call (its name and command or file, 200 characters); tool results dropped. Over $SANDMAN_DIGEST_BYTES (300 000) it keeps the head and the tail, whole lines, and the middle becomes … <n> bytes omitted ….
  • model run — shared by both jobs: $SANDMAN_ENCODER here, a command line run by sh -c in its own process group with CLAUDE_MEMORY_PIPELINE=1 and SANDMAN_NO_TAKE=1, so a session it starts is never taken; by default a headless Claude Opus with no tools, no hooks, MCP servers or CLAUDE.md, and no saved session: claude -p --model opus --output-format text --safe-mode --tools "" --no-session-persistence. Its stdin is the guidance, the contract and the data; its stdout one object, text around it ignored; exit 0.
  • sign-in — the stored interactive login expires; a token file outlives it, a year. Read at each run, so a replaced file needs no restart: $SANDMAN_CLAUDE_TOKEN_FILE, else ~/Codes/claude-oauth-token, a regular file no group or other can read, its trimmed text set as CLAUDE_CODE_OAUTH_TOKEN for the command alone. The line's token says which, never the value: absent without the file (the stored login, as before), the path when used, refused: <path>: mode <octal>, want a regular file of mode 600 or ignored: <path> is empty, the run going ahead without it.
  • prompt — two parts. The contract (src/prompts/encode.contract.md) fixes the input layout and the reply's shape; it is built in and always sent, so no edit can break parsing. The guidance, what a trace is and how to word one, is <root>/prompts/encode.md when that file holds any text, else the built-in default (src/prompts/encode.md), so it changes without a rebuild. A local model replaces Opus with any command that keeps the contract: 
    {"traces":[{"type":"user"|"feedback"|"project"|"reference"|"knowledge"|"playbook","name":str,"description":str,"body":str,"about":str|null,"topic":str|null}]}
  • homing — sessions start from one root directory and dispatch work into many repositories, so a session's cwd says little about what a fact concerns. A knowledge or playbook trace names its topic, a slug (lowercase letters, digits, -), and lands in traces/@<topic>/ (the knowledge store); a type without one fails the episode. Any other trace names its repository in about; the bank is that directory's key when it is an absolute path to an existing directory, else the episode cwd's, else $HOME's. A key is the earlier sandman's: the directory a linked worktree sits in, the checkout a nested worktree belongs to, else the directory itself, every byte not alphanumeric -. The trace lands at traces/<bank>/<type>_<slug>.md by temp file and rename, the slug the bank format's (the name lowercased, non-alphanumeric runs _, 60 characters), _2, _3 on a clash.
  • stop — a stop signal or shutdown request kills the model's group and writes no line, so the job runs again after the next start. failed is final: the tick never retries it; removing its line from the ledger does.

consolidate

A job of serve's tick, in place of the dream pass: it stabilises a bank's traces and integrates them with what the bank holds. A trace that revises a memory updates it (reconsolidation); pruning drops a trace that does not hold or a memory gone stale. Nothing waits for a person.

It runs only in a tick with no episode to encode, one bank at a time, derived from disk each tick: of the banks under traces/, a topic's @<topic> among them, whose newest trace's created is older than $SANDMAN_CONSOLIDATE_QUIET_MS (600 000, so a burst of episodes lands first), the one with the oldest trace. A bank whose last consolidate failed waits for a trace newer than the failure, so a bad reply never storms. The model run is encode's, with $SANDMAN_CONSOLIDATOR and $SANDMAN_CONSOLIDATE_MS (600 000), its guidance <root>/prompts/consolidate.md else the default, then its contract (src/prompts/consolidate.contract.md), then the bank. A topic's runs the same way with knowledge/<topic>/ in place of memories/<bank>/, and its keeps take knowledge or playbook only (how a page is written):

  • checked — every trace named by exactly one op, every file named present in the input, a memory named at most once and never a listed one; otherwise the whole reply is rejected and nothing changes.
  • applied — every write staged beside its target first (a failure removes them and fails); then every named trace, and every merged or pruned memory as it stood, renamed to .pruned/<yyyy>/<mm>/<dd>/<HHMMSS>-<bank>-<file> beside the reply, …-<bank>-ops.json, reasons included; then the writes renamed in. Nothing is deleted.
  • stamped — a kept or merged memory's source is consolidate <now> · <the trace's session> · model=<model>; a merge replaces the earlier one, as the bank format's own rewrites do, and the replaced version keeps it under .pruned/.   • stop — as encode's: no line, the bank runs again after the next start.

reflect

A job of serve's tick, the weekly review: the pipeline rewrites the guidance encode and consolidate run on from evidence of what they did, and adopts a rewrite only when a replay judges it no worse. No step waits for a person; the contracts stay fixed in the binary.

It runs only in a tick with no rollback due, no episode waiting and no quiet bank; at most once per $SANDMAN_REFLECT_MS (604 800 000, a week) after this machine's latest reflect line, and only when at least $SANDMAN_REFLECT_MIN (5) encode or consolidate model runs follow it: no evidence, no run and no line. The model run is encode's, with $SANDMAN_REFLECTOR and $SANDMAN_REFLECTOR_MS (600 000), its guidance <root>/prompts/reflect.md else the default (src/prompts/reflect.md), then its contract (reflect.contract.md), then:

Consolidate's are the latest .pruned/ replies, each bank rebuilt: the traces it consumed and the memories it merged or pruned as they stood, beside the bank's other memories now, less those whose created and session match a consumed trace (its keeps). A later run's changes to those others show through: close, not exact.
  • adopt — the guidance in force, the built-in default included, copied to prompts/.history/<yyyy>/<mm>/<dd>/<HHMMSS>-<job>.md, then the new one written to prompts/<job>.md by temp file and rename; the job's next run reads it.
  • roll back — when the latest reflect line adopted a job and that job's first two model runs since both failed, the next tick, before any other job, restores the version the line kept, the failing one kept under .history/ in turn: outcome reverted. Any later reflect line ends the watch.
  • stop — as encode's: the group killed, no line, the review again after the next start. Every other outcome, failed too, waits out the week.
