sandman · recall

memory for agentic sessions · the main page

recall is the agent's tool: it pulls the memories that bear on what it is about to do, by its own cue, whenever it needs them. A session's start gets a seed.

Partly built: sandman recall and sandman show run (the agent's tools); the seed, the mod wiring, the Kev fallback, remember and the pane are not, and the earlier sandman's recall runs at every session's start. A decision is open until its badge says settled.

The problem

Today the mod runs the earlier sandman recall --hook on a session's first prompt, awaits it (10 s timeout) and injects up to 10,000 characters. That recall never sees the prompt: it walks from the cwd's bank up through ancestor banks, never down, inside a 9,000-character budget.

Sessions start from one root directory and dispatch work into many repositories. From there the walk reaches 2 banks and, after its budget cuts, injects 31 index lines; every bank below the root is out of reach.

The flow

Two ways in, one scoring: the seed once at the first prompt, the agent's pull at any time.

When does it run?

settled

Whenever the agent needs it: recall is the agent's tool, pulled throughout a session with its own cue — what it is about to do, the repository it is entering, the decision it is about to make — through the CLI now and an MCP tool later. Nothing in the mod calls a model per prompt.

The session's start is a seed, the one verb the mod runs there: ① the start mark, first and whatever follows, so mark keeps only calls and prompts and the short-term pointer goes; ② short instructions saying memory exists and when and how to pull it (the draft); ③ the always-set; ④ memories for the first prompt, only when it carries a real ask that scores well.

  • Most detailed asks come later or out of the agent's own discovery, so the seed matters and the pulls carry the weight.
  • After /clear the seed runs again without a start mark: the session is the same one.

Proposed: it is the house order, Jev then local Kev then an error, kept inside the same wait.

  • Kev runs about 43 ms a question (50 in 2.0 s, 150 in 6.5 s): all 645 would take about 28 s. The banks take about 2 s, which leaves room for some 20 memories in the second stage.
  • Out of tokens counts as down. Both down is the always-set and an error in the pane, never a silent empty recall.

Hosted or local?

settled

Hosted Jev scores, and the user memories are never candidates: they always come along unscored, as the always-set, pinned memories with them. Each pull sends to api.typesafe.ai the cue and every other memory's name and description beside the fixed question, about 260 KB: repository names, paths, rules.

The agent's tools

recall pulls, remember writes; the contracts are in AGENTS.md, and an MCP tool of the mod's server carries the same three later.

  • sandman recall --cue "…" [--session <uuid>] [--budget <chars>] built — one noul a candidate through $SANDMAN_SYSTEMONE (default: curl to Jev, the key as curl config on its stdin, never in an argv); stdout the digest, stderr one stats line, one ledger line; within a session, nothing already sent is sent again.
  • sandman show <bank>/<file>.md [--session <uuid>] built — the memory's body under its name, type and date, and a ledger line; anything that is not a memory file under the banks is refused.
  • sandman remember "<body>" [--type user|feedback|project|reference] [--name …] [--about <path>] [--session <uuid>] not built — encodes on purpose: a trace written at once to traces/<bank>/ (source remember <ISO> · <session>), homed by --about as an encoded trace is (none: about the person, or true everywhere), and a ledger line. Traces then join recall's candidates, marked ~ until consolidation keeps, merges or prunes them, and the episode's encode takes what was remembered as done. Until it lands, the earlier sandman's remember writes straight into a bank.

The seed's instructions, not built, the mod filling in the session id:

Memory from earlier sessions is yours to pull. Run `sandman recall --session <id> --cue "<what you are about to do>"` before starting work in a repository, before a choice the person may already have ruled on, and when a correction lands that may already be recorded. Each line is a pointer, not the memory: read it with `sandman show <bank>/<file>` before acting on it. Don't recall every turn. When the person states a preference, corrects you, or decides something a later session needs, run `sandman remember "<their words>"` at once: one fact per call.

Risks

  • injection — memories are written unattended from transcripts, so a name or description can argue for its own selection. The description is capped at 160 characters, the memory travels as data beside a question fixed in the binary that says so, and reflect watches for memories sent often and never used.
  • the number — a noul ranks well but is not a calibrated probability: the 0.5 floor only drops what Jev leans against, and the budget does the rest.
  • estimates — Jev's time, tokens and cost for the whole corpus are inferred, not measured; the first recall lines settle them, and whether the question must shorten to fit one request.
  • hosted dependence — the good path needs api.typesafe.ai; an outage degrades every session to Kev's narrow pass.

Open questions
