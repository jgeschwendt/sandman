sandman · recall

memory for agentic sessions · the main page

recall is the agent's tool: it pulls the memories that bear on what it is about to do, by its own cue, whenever it needs them. A session's start gets a seed.

Partly built: sandman recall, the seed and the pull, sandman show and sandman remember run (the tools), on one local Ollama (needs); the mod wiring and the pane are not, and the earlier sandman's recall runs at every session's start. A decision is open until its badge says settled; the pipeline and its cut are the evaluation's choice.

The problem

Today the mod runs the earlier sandman recall --hook on a session's first prompt, awaits it (10 s timeout) and injects up to 10,000 characters. That recall never sees the prompt: it walks from the cwd's bank up through ancestor banks, never down, inside a 9,000-character budget.

Sessions start from one root directory and dispatch work into many repositories. From there the walk reaches 2 banks and, after its budget cuts, injects 31 index lines; every bank below the root is out of reach.

The flow

Two ways in, one pass: the seed once at the first prompt, the agent's pull at any time.

The ten candidates go in one request. The decision model's card calls one question a request the safer default; here it scored lower on every measure and took 1.8 times as long, since the local server answers one request at a time. The request shape moves a candidate's score by .13 on average, and a rerun of either shape is identical, so the gap is the shape's and not noise (measured 2026-11-13 · the evaluation's shape table).

What still gets missed

open

The scorers read a name and 160 characters of description, so the remaining losses come from the memories as much as the scoring: a rule for every repository whose description hides when it applies, a name that is a date or a sentence, a memory filed under another repository's bank. Encode and consolidate guidance shapes new memories built.

  • redescription — a dry run of a one-time rewrite exists: 303 names, 607 descriptions and 177 homes would change. It is measured on this pipeline before any memory is edited planned.
  • stale and duplicated — the same pass flags 93 memories as stale and 62 as duplicated; listed, not acted on.

  • BM25 reads <label> · <name>, the description one-lined to 400, the body and the file's stem; the embedding the same head and the body's first 1,500 characters, with qwen3-embedding:0.6b (1,024 dimensions, 1,024 tokens). The labels come from the grove root's owner and repository dirs, so a worktree's bank reads as its repository (AGENTS.md).
  • The vectors live in <root>/embeddings.jsonl, keyed by the text's SHA-256, so the evaluation's own cache reads here unchanged. serve's tick embeds what is missing, 128 a tick; a pull embeds at most 8 more, the lexically best, and one still missing ranks lexically only.
  • The decision model sees each of the ten as Memory (<label>): <name> — <description, 160>. <question> beside the state.
  • Traces are candidates too, from the moment they are written: a remember made at 10:05 is recallable at 10:06, marked ~ until consolidation keeps, merges or prunes it; a user trace rides the always-set.

What comes along without a vote?

settled

Every user memory, plus any pinned: facts about the person bear on every session whatever the cue. They ride the seed only, counted first against its budget: 18 lines today, about 3,600 characters. A pull never prints them; at the default 4,000 a pull that did had room for nothing else.

  • Pinning is the format's recall: field, written from the pane; no memory carries it today.
  • When the set passes half the seed's budget, the cap or the set is the next decision.

When does it run?

settled

Whenever the agent needs it: recall is the agent's tool, pulled throughout a session with its own cue — what it is about to do, the repository it is entering, the decision it is about to make — through the CLI or the same verbs as MCP tools. Nothing in the mod calls a model per prompt.

The session's start is a seed, the one verb the mod runs there: ① the start mark, first and whatever follows, so mark keeps only calls and prompts and the short-term pointer goes; ② short instructions saying memory exists and when and how to pull it (as shipped); ③ the always-set; ④ memories for the first prompt, only when the gate finds a real ask.

  • After /clear the seed runs again for the same session: a second start mark (chart keeps the earliest), and nothing an earlier recall sent is sent again.

What does the seed wait for?

settled

At most 4 s for the whole pass, every embedding and every scorer tried ($SANDMAN_SEED_MS), inside the mod's 10 s; a pull has $SANDMAN_RECALL_MS, 10 s. Over the real corpus of 635 a pull takes about 0.95 s with pplx answering, 0.27 s with no decision model and 0.14 s with neither, the read of the 14 MB cache included (measured 2026-11-13, an idle Ollama). The seed never fails the prompt: past the bound it prints what the stages that answered allow, exits 0 and records why. ① is written before any of it, so nothing loses the start mark.

What happens when a model is down?

settled

Each stage drops out within the same bound and the rest answer, never an error to the agent: the embeddings down, the decision runs on BM25's order; a decision model down, the next in $SANDMAN_SCORERS (pplx,kev,jev), each sent the same request; none, the hybrid cut; nothing, the lexical cut. The header names the path and what failed (· pplx, · kev: pplx failed, · hybrid, no decision model, · lexical: embed and pplx and kev and jev failed) and the ledger line keeps each cause.

  • Down is a refused connection, a timeout, an HTTP error, a reply without a noul or an embedding per text, or Jev without a key. A missing model in Ollama falls through the same way.
  • Jev out of credit or refused (billing_error, 401, 402, 403) is held down for 6 hours, anything else for 60 s, in <root>/jev-down.json; while it holds, Jev is skipped.

Hosted or local?

settled

Local: both models run on this machine, and nothing leaves it unless hosted Jev is placed in the scorer order and reached, which today needs pplx and Kev to fail first. Then the cue and ten names, descriptions and repository labels go to api.typesafe.ai; bodies never do. The user memories and pinned ones are never candidates: they ride the seed unscored.

The tools

The seed is the mod's, recall and show the agent's, remember its write, each a command and the agent's three also MCP tools; the contracts are in AGENTS.md.

  • sandman recall < {"session","prompt"?,…} built — the seed, once at the first prompt: ① the start mark, first and whatever follows; then, within 9,000 characters, the instructions with the session id, the always-set, the prompt's ranked lines when the gate finds an ask, and the footer; past 4 s, what the stages that answered allow. CLAUDE_MEMORY_PIPELINE=1: the start mark only. Bad stdin: exit 2, nothing written.
  • sandman recall --cue "…" [--about <path>] [--session <uuid>] [--budget <chars>] built — the pull: the flow, every transport curl (Jev's key as curl config on its stdin, never in an argv); stdout the header, the ranked lines and the footer, never the always-set; stderr one stats line; one ledger line; within a session nothing already sent, by the seed or a pull, is sent again.
  • sandman show [traces/]<bank>/<file>.md [--session <uuid>] built — the memory's or trace's body under its name, type (a trace says so) and date, and a ledger line; a memory is <bank>/<file>, a trace traces/<bank>/<file>, anything else refused.
  • sandman remember "<body>" [--type user|feedback|project|reference] [--name …] [--description …] [--about <path>] [--session <uuid>] built — encodes on purpose: one trace written at once to traces/<bank>/, source remember <ISO> · <session>, homed by --about as an encoded trace is, else by the cwd (from the root: about the person, or true everywhere); defaults feedback, the body's first eight words, its first line. It prints the show line to read it back and writes a ledger line; encode never writes it again, and consolidation takes it like any other trace.
  • sandman mcp built — the three as MCP tools over stdio, recall {cue, about?, budget?}, remember {body, about?}, show {path}, each description the seed's when-to-pull line; a call runs the verb itself, so its text, ledger line and de-duplication are the command's, and a failure is a tool result flagged isError carrying the verb's error line. The session is Claude Code's $CLAUDE_CODE_SESSION_ID, which it gives every stdio server, unless a call passes session. Registered once, by the owner: claude mcp add --scope user sandman-next -- ~/.local/bin/sandman-next mcp.
  • Every command printed for the agent names the binary as invoked: sandman-next today.

Risks

  • injection — memories are written unattended from transcripts, so a name or description can argue for its own selection. Planted beside the corpus, a memory claiming it applies to every request came back in 5 of 15 robustness cues; withholding the bank bonus from any name or description that claims its own importance cut that to 2 of 15 with the headline unchanged, and no real memory matches the pattern (measured 2026-11-13). The description is capped at 160 characters, the question is fixed in the binary, and reflect watches for memories sent often and never used. A stricter question measured as noise and is not shipped.
  • the number — a fused score ranks; it is not a probability, and the floors are where this corpus's scores fell.
  • one server — the best path needs the local Ollama and both models resident; without it every pull is the lexical cut, .12 less must-recall (needs).

What must be running

One Ollama at $SANDMAN_OLLAMA (http://127.0.0.1:11434) holding qwen3-embedding:0.6b (Q8_0) and pplx-decider-flash:4b, a System One decision model, about 6 GiB resident together; Kev on 127.0.0.1:1703 is the next scorer, hosted Jev the last. Without Ollama, recall answers from BM25 alone and says so; without the cache, a pull embeds 8 and the tick fills the rest.

next Native inference, without Ollama: llama-cpp-2 matches it over 98 cues (precision .650 against .648, must-recall .620 against .611) at the same speed; candle has no Qwen3.5 / Gated-DeltaNet model as of 0.11.1. The shape is a supervised sandman-infer child binary behind the same scorer seam, about 3–4 days, after the mod wiring; until then Ollama is the shipped path.
