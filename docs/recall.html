sandman · recall

memory for agentic sessions · the main page

recall is the agent's tool: it pulls the memories that bear on what it is about to do, by its own cue, whenever it needs them. A session's start gets a seed.

Partly built: sandman recall, the seed and the pull, sandman show and sandman remember run (the tools), Jev then local Kev then the lexical rank alone; the mod wiring and the pane are not, and the earlier sandman's recall runs at every session's start. A decision is open until its badge says settled; the gate, the prefilter, what each scorer sees, the blend and the cut are the evaluation's choice.

The problem

Today the mod runs the earlier sandman recall --hook on a session's first prompt, awaits it (10 s timeout) and injects up to 10,000 characters. That recall never sees the prompt: it walks from the cwd's bank up through ancestor banks, never down, inside a 9,000-character budget.

Sessions start from one root directory and dispatch work into many repositories. From there the walk reaches 2 banks and, after its budget cuts, injects 31 index lines; every bank below the root is out of reach.

The flow

Two ways in, one scoring: the seed once at the first prompt, the agent's pull at any time.

What did the evaluation choose?

settled

A hybrid: a free lexical gate, a free BM25 prefilter over each memory's whole text that keeps 39, one model request over those 39 (Jev while hosted credit lasts, local Kev otherwise), the noul blended with the lexical score, then a floor and a cap per scorer.

Where they are still lost: .13 never reach the 39 (the prefilter), .17 with Jev and .23 with Kev rank past the cap (the scorer), and almost none fall to the floor (the cut).

What still gets missed

open

The scorers read a name and 160 characters of description, so the remaining losses come from the memories as much as the scoring: a rule for every repository whose description hides when it applies, a name that is a date or a sentence, a memory filed under another repository's bank. Encode and consolidate guidance shapes new memories built.

  • redescription — a dry run of a one-time rewrite exists: 303 names, 607 descriptions and 177 homes would change. On Kev it adds .03 precision and .01 must-recall; it is measured on Jev before any memory is edited planned.
  • stale and duplicated — the same pass flags 93 memories as stale and 62 as duplicated; listed, not acted on.

What comes along without a vote?

settled

Every user memory, plus any pinned: facts about the person bear on every session whatever the cue. They ride the seed only, counted first against its budget: 18 lines today, about 3,600 characters. A pull never prints them; at the default 4,000 a pull that did had room for nothing else.

  • Pinning is the format's recall: field, written from the pane; no memory carries it today.
  • When the set passes half the seed's budget, the cap or the set is the next decision.

The house rule for context injection: one line per item plus a verb to read one in full. A read through show writes a ledger line, so line-then-read is also the use signal record needs; a body sent whole leaves no trace of whether it helped. The bank shows as its key, the path show takes.

The lexical score is a candidate's BM25 plus its bonus over the top one among the kept. The floor is on the final score; a line shows the noul (the lexical score when unscored). Then the characters: 9,000 for the seed, 4,000 for a pull, under the 10,000 session-start cap; a cue with no ask gets nothing.

The ledger tunes them next: how far down the ranking a read memory sat says whether they are right. $SANDMAN_<JEV|KEV|LEXICAL>_<W|FLOOR|MAX>, $SANDMAN_RECALL_N, $SANDMAN_SEED_N, --budget and $SANDMAN_SEED_BUDGET move them.

When does it run?

settled

Whenever the agent needs it: recall is the agent's tool, pulled throughout a session with its own cue — what it is about to do, the repository it is entering, the decision it is about to make — through the CLI now and an MCP tool later. Nothing in the mod calls a model per prompt.

The session's start is a seed, the one verb the mod runs there: ① the start mark, first and whatever follows, so mark keeps only calls and prompts and the short-term pointer goes; ② short instructions saying memory exists and when and how to pull it (as shipped); ③ the always-set; ④ memories for the first prompt, only when the gate finds a real ask.

  • Most detailed asks come later or out of the agent's own discovery, so the seed matters and the pulls carry the weight.
  • After /clear the seed runs again for the same session: a second start mark (chart keeps the earliest), and nothing an earlier recall sent is sent again.

What does the seed wait for?

settled

At most 4 s for the whole pass, gate, prefilter and every scorer tried ($SANDMAN_SEED_MS), inside the mod's 10 s; Kev on the seed's 20 measured p50 1.9 s, p90 2.5 s. A pull has $SANDMAN_RECALL_MS, 10 s; Kev on 39 measured p50 3.7 s, p90 4.9 s. The seed never fails the prompt: past the bound it prints the instructions, the always-set and the lexical rank, marked unscored, exits 0 and records why. ① is written before any of it, so nothing loses the start mark.

Unmeasured until hosted credit returns: Jev's latency for one 39-question request, score stability under reruns, and resistance to memories that argue for their own selection.

What happens when Jev is down?

settled

Kev scores the same candidates within the same bound, and when Kev fails too the lexical rank alone answers: never an error to the agent. The header names the scorer (· jev, · kev, · lexical, unscored: jev and kev failed) and the ledger line keeps each failure.

  • Down is a missing key, a transport failure, a timeout or an HTTP error. Out of credit or refused (billing_error, 401, 402, 403) holds Jev down for 6 hours, anything else for 60 s, in <root>/jev-down.json; while it holds, Kev goes first.
  • $SANDMAN_SCORER (jev, kev, none) forces one.

Hosted or local?

settled

Hosted first, local when hosted is down. Only the cue and about 39 names, descriptions and repository labels leave the machine, and only while hosted credit lasts; bodies never do, and Kev sends nothing off it. The user memories and pinned ones are never candidates: they ride the seed unscored.

The tools

The seed is the mod's, recall and show the agent's, remember its write; the contracts are in AGENTS.md, and an MCP tool of the mod's server carries the agent's three later.

  • sandman recall < {"session","prompt"?,…} built — the seed, once at the first prompt: ① the start mark, first and whatever follows; then, within 9,000 characters, the instructions with the session id, the always-set, the prompt's ranked lines when the gate finds an ask, and the footer; past 4 s, the lexical rank, marked unscored. CLAUDE_MEMORY_PIPELINE=1: the start mark only. Bad stdin: exit 2, nothing written.
  • sandman recall --cue "…" [--about <path>] [--session <uuid>] [--budget <chars>] built — the pull: the gate, the prefilter, one request to Jev through $SANDMAN_SYSTEMONE (default: curl, the key as curl config on its stdin, never in an argv), else Kev through $SANDMAN_KEV (default: curl to the local server); stdout the header, the ranked lines and the footer, never the always-set; stderr one stats line; one ledger line; within a session nothing already sent, by the seed or a pull, is sent again.
  • sandman show [traces/]<bank>/<file>.md [--session <uuid>] built — the memory's or trace's body under its name, type (a trace says so) and date, and a ledger line; a memory is <bank>/<file>, a trace traces/<bank>/<file>, anything else refused.
  • sandman remember "<body>" [--type user|feedback|project|reference] [--name …] [--description …] [--about <path>] [--session <uuid>] built — encodes on purpose: one trace written at once to traces/<bank>/, source remember <ISO> · <session>, homed by --about as an encoded trace is, else by the cwd (from the root: about the person, or true everywhere); defaults feedback, the body's first eight words, its first line. It prints the show line to read it back and writes a ledger line. The episode's encode lists what the session remembered under # already remembered, which the contract forbids writing again, and drops a highlight with the same body; consolidation takes the trace like any other.
  • Every command printed for the agent names the binary as invoked: sandman-next today.

Risks

  • injection — memories are written unattended from transcripts, so a name or description can argue for its own selection. The description is capped at 160 characters, the memory travels as data beside a question fixed in the binary that says so (its resistance is unmeasured), and reflect watches for memories sent often and never used.
  • the number — a noul ranks well but is not a calibrated probability: the floors and weights are where this corpus's scores fell, and move with it.
  • hosted dependence — the best path needs api.typesafe.ai and its credit; without them every pull is Kev's, .06 less must-recall.
