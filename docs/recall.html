sandman · recall

memory for agentic sessions · the main page

recall is retrieval: at a session's start it takes what the person just asked as the cue and brings the memories in the banks that answer it into the session's context.

Design, not built. The earlier sandman's recall runs today. Each decision below is open until its badge says settled.

settled recall is the one verb the mod runs at a session's start; it writes the start mark to the ledger first, before anything slow, whether or not there is anything to recall; mark then keeps only calls and prompts; the short-term pointer goes when this recall replaces the earlier one.

The problem

Today the mod runs the earlier sandman recall --hook on a session's first prompt, awaits it (10 s timeout) and injects up to 10,000 characters. That recall never sees the prompt: it walks from the cwd's bank up through ancestor banks, never down, inside a 9,000-character budget.

Sessions start from one root directory and dispatch work into many repositories. From there the walk reaches 2 banks and, after its budget cuts, injects 31 index lines; every bank below the root is out of reach.

The proposed flow

One request, every memory a candidate, the prompt as the cue. Each decision below can change a box; the figure follows the proposed option of each.

Proposed: one Jev request holds the whole corpus, so nothing needs narrowing.

  • Each candidate is its name and its description cut at 160 characters: 25.7 KB of names plus about 95 KB of capped descriptions, about 50k tokens, inside Jev's 64k a request.
  • Uncapped, the descriptions are 181.7 KB (average 269 characters, longest 1,392; only 184 are within 160): the cap is what makes one request fit, and it trims the room a description has to argue for itself (risks).
  • Headroom: about 14k tokens, some 180 more memories at the current average, before the corpus needs a first stage or a tighter cap.

What happens when Jev is down?

open
optionwhat it meanscost
Kev in two stages, inside the bound proposed49 banks by their path, then the top banks' memories; past the bound, the always-setabout 20 memories scored, not 645; lower quality
the earlier deterministic orderthe cwd chain, as todaykeeps a selection the design exists to replace
fail loudly onlythe always-set and an erroran unscored session at every Jev outage

Proposed: it is the house order, Jev then local Kev then an error, kept inside the same wait.

  • Kev runs about 43 ms a question (50 in 2.0 s, 150 in 6.5 s): all 645 would take about 28 s. The banks take about 2 s, which leaves room for some 20 memories in the second stage.
  • Out of tokens counts as down. Both down is the always-set and an error in the pane, never a silent empty recall.

Hosted or local?

Proposed: sent, then read, then pinned or muted is the whole feedback loop, and two of its three parts exist already.

  • use — a later read of a sent memory's file in the same session, from the tool log (194 such reads on record) and, once mark carries calls, from the ledger.
  • pin, mute — from the pane: the memory's recall: field and a ledger line.
  • reflect reads these to tune the selection question and the memories' descriptions; consolidate keeps its merge and prune ops.

The pane

Today the mod's pane shows one row per injected block, ▸ hh:mm · sandman recall · <n> chars, expanding to the whole text dimmed. The engine allows a working list.

keydoesrecords

mmutes: never a candidaterecall: mute on the memory, a ledger line
rrecalls again, the cue the latest prompta new recall line
  • engine — a Button with a hotkey per row, Text colour and dim for scores and descriptions, a Link to open the file, scroll while focused, refresh on r.
  • width — a dock up to 45 % of the terminal's columns, opened at 144 columns or more; under that, an inline pane a third of the rows high.

Risks

  • injection — memories are written unattended from transcripts, so a name or description can argue for its own selection. The description is capped at 160 characters, the question is fixed in the binary and never read from a memory, and reflect watches for memories sent often and never used.
  • the number — a noul ranks well but is not a calibrated probability: recall ranks and fills a budget, never thresholds.
  • estimates — Jev's time and cost for one 645-candidate request are inferred, not measured; the first recall lines settle them.
  • hosted dependence — the good path needs api.typesafe.ai; an outage degrades every session to Kev's narrow pass.

Open questions

  • Scores in the pane as numbers or as bars?
  • A recalled memory's bank shown as the repository's name or as the bank key?
  • Does r take the latest prompt as the cue, or ask for one?
